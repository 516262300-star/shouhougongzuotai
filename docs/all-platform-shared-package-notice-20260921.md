# 全平台同包裹部分订单退款转人工

用户于2026-09-21确认：规则适用于所有平台，但只核对同一个发货包裹；同客户不同运单的订单不纳入该包裹。目标订单申请全额退款，不等于整个包裹都可以拦截。

## 执行规则

- 企微桌面和备用webhook入口都在认领发送任务前调用统一包裹检查。没有核验通过凭据不能输入或发送；发送前再次核对订单快照、人工锁及80秒证据时效。
- 拼多多、天猫、淘宝从ERP唯一客户的完整原销售分页确定候选订单，用对应平台和店铺只读授权逐笔核对订单、发货运单、快递公司及退款明细。淘宝使用淘宝专用授权，不借用天猫凭据。
- 同包裹中存在没有申请有效全额仅退款的订单或商品时，取消尚未发送的同包裹拦截任务，转人工处理。业务员从每笔退款申请对应的原销售订单确定，同业务员的同包裹事项合并；发送前重新核实归属。缺失或冲突时留在待办队列等待核实，不能随意分给客户档案上的默认业务员。
- 同客户其他运单经平台确认后排除；仅金额合计相等、本地没有其他售后记录或客户昵称相同，都不能证明包裹允许拦截。
- 京东、抖音、1688当前没有接入完整的整包裹退款核验。其拦截任务若到达发送入口，一律停止自动拦截、生成包裹范围待核实的人工待办，由原销售业务员确认。文案明确资料尚未核实，不假称已经查证部分退款。当前这些平台仍沿用原只读/人工业务范围，本次不启用它们的自动拦截或退款。
- 其他未适配平台也不能因缺少专用分支直接通过。拼多多及淘系暂时查询失败、漏页、身份冲突或证据过期时，保持未发送，原任务五分钟后自动只读重查，不堵住其他包裹。

已发送或结果不明的消息、原人工待办与资金凭证保留，不删除后重发，不自动撤销快递已接收的指令。既有人工锁不因后续退款状态变化自动解除。没有新增退款权限或多订单自动实收分配。

## 运行与恢复

沿用正式Worker原周期、发送开关、归属重查及人工待办发布器，无新增定时任务、环境变量或数据库迁移。仅替换统一发送检查、淘系只读核验、备用动作执行器和待办文案/原因分类相关文件。

正式发布前核对当前Worker源文件，与本次补丁基线逐项比对；在复制出的候选版本运行相关回归测试。维护期间等待原周期自然结束，完成可验证的数据库与运行文件备份后切换Worker指针，由原守护任务在交互桌面会话恢复。保留Web及独立揽收提醒指针，不重放历史个案脚本。

查询异常由后台按原周期重查。已转人工的包裹由业务员核实后处理，不能通过批量重置任务状态绕开人工锁。回退时须先暂停通知发送，旧版本缺少全平台统一检查，不能直接带着待发队列恢复发送。
