# 办公室双机使用说明

## 日常使用

- 开发机：继续在原项目目录修改、测试代码；桌面的“售后工作台-正式版”打开运行机的实时业务数据。开发机关机不影响运行机。
- 正式运行机：独立保存数据库、运行网页和业务后台，通过本机企业微信发送拦截通知。运行目录为 `D:\LDSAftersales\app`。
- 运行机的 `AfterSales-Local` 桌面入口使用 `http://127.0.0.1:8000/`，可进行受本机来源限制的管理操作。开发机通过运行机的局域网网址访问；局域网开放不取消已有管理权限限制。
- 两台电脑显示正式业务时访问同一个运行机服务。开发机旧数据库保留为停写后的独立测试副本，开发数据不会自动回灌正式库。

## 保持运行

运行机保持接电、开盖、Windows 已登录且桌面未锁定，企业微信保持登录。接电时已关闭系统自动休眠、休眠到磁盘和熄屏；未修改 Windows 密码、自动登录或锁屏安全策略。

SSH 和 MySQL 是自动启动的 Windows 服务；网页与业务后台由 `Leedis Aftersales Module1 Watchdog` 在运行账户登录时启动，并每 5 分钟检查一次。任务使用实际桌面账户的 Interactive/Limited 会话，不在 SSH 会话中运行企微发送器。重启后仍须登录 Windows 并确认企微在线。2026-09-12 已实际完成整机重启、用户登录及自动恢复验收，首个业务周期于 15:38:40 正常完成；详细证据见[备份与验收说明](office-backup-and-acceptance-20260912.md)。

守护入口已改为 `pythonw.exe` 加无控制台 PowerShell，消除每次检查时黑色终端窗口闪现；周期和自启动保持原设置。启动异常可查 `.runtime/module1-autostart-launcher.log`，见[黑窗修复与验证](wecom-console-flash-20260912.md)。

建议由网络管理员在路由器保留两台电脑当前 DHCP 地址。部署 SSH 与网页防火墙仅允许已登记的开发机地址；地址变化需同步核对设置，不能为省事关闭防火墙。

## 程序更新

1. 在开发机完成修改及对应验证，将本次代码和说明提交 GitHub；不发布尚在开发的其他改动。
2. 准备已验证的 Worker/Web 发布目录，更新相应发布指针，再用 `scripts/build_office_release.py` 生成新的代码包。工具打包指针指定的稳定版本，不会自动收集所有开发改动。
3. 经已校验主机身份的受限 SSH/SFTP 将包传入运行机的 `incoming`，在新目录解包并核对逐文件 SHA-256、依赖及 schema 要求。保留旧发布版本。
4. 切换前暂停守护，等待当前业务周期安全结束；涉及数据库迁移时停止全部写入并做一致性备份。切换配套 Web/Worker 指针后，通过实际桌面账户的守护任务恢复，验证网页、数据库、周期和企微状态。
5. 程序更新保留正式数据库、环境配置、账本、幂等记录及监控状态。不能把开发库、空账本、旧备份或整份开发目录覆盖上去。回退仅选兼容当前 schema 的代码；数据库回退应另行核对，不能丢弃升级后的新业务。

## 数据与备份

MySQL 数据位于 `D:\LDSAftersales\mysql-data`；发送账本和监控状态位于 `D:\LDSAftersales\app\.runtime`。数据库只监听运行机本地，不通过网络共享 MySQL 数据文件。

本次迁移在两台电脑均保留最终快照，运行机副本位于 `D:\LDSAftersales\backups\final`，包含业务数据库、发送账本、监控状态、发布指针、环境配置及核验清单。快照包含敏感资料，不能提交 GitHub或放进普通代码包。

2026-09-12 已配置运行机每天 04:30 备份到 `D:\LDSAftersales\backups\daily`，开发机登录及每两小时通过受限 SSH 拉取最新成功副本到项目 `.runtime/office-deployment/backups`。开发机离线时运行机仍备份，异机副本等重新联网后更新。已完成首份备份、两机校验及 21 张表的隔离恢复；详见[备份与验收说明](office-backup-and-acceptance-20260912.md)。
