# 模块1：同包裹未申请退款保护

> 2026-09-10 审计修复：资金请求防重、异常响应、独立质检和发送回执规则已有调整；以[安全修复与部署说明](audit-safety-fixes-20260910.md)为准。代码准备不代表生产已部署或已验收。

2026-09-09。用户确认新增规则：已发货、尚未揽收的仅退款订单，如果同包裹还有订单未申请退款，不能自动给当前申请单退款，应通知客户档案对应业务员联系客户。之前处理过指定个案不代表已有自动保护，本次才接入通用资金执行器。

## 判断及范围

保护默认生效，没有可单独关闭它的环境开关。当前覆盖拼多多模块1的双接口无轨迹风险退款、接口明确待揽收102、人工确认未揽收应急路径。正常在途退款只检查是否已有同包裹人工锁，不扩展其他平台退款权限或模块2退货实物分配。

1. 沿用原全额仅退款、当天/24小时发货、物流历史、成功发群、客服工作时间及资金权限检查。
2. 通过目标平台订单实时找到唯一 ERP 客户ID，验证客户档案提供的销售页ID，使用 `shipment?kehuid=客户ID&page=0` 及后续全部分页读取原销售商品行。不能仅用客户名称、目标快递单号过滤，也不能只查工作台售后表。
3. 通过“原销售商品行的客户编号”提取平台订单号，“订单编号”是内部销售ID，不互换。只明确排除退货单、税点、运费。缺失平台关联、隐藏列、空页、页码异常、重复页、跨店查询无权限都不当作没有其他订单。
4. 使用目标店铺只读凭据逐笔实时查平台订单，按 **快递公司＋完整发货运单号** 核对包裹；同客户但其他快递包裹明确排除。不凭同型号或同一 ERP 销售单推断合包。
5. 同包裹 `refund_status=1` 明确未申请退款时阻断。其他关联单需读取最新售后详情，只有有效全额仅退款（待商家处理或已成功）才算本保护检查覆盖；部分补偿、退货退款、关闭/撤销等需要业务员核实，未知字段或接口失败停在本地待核实。
6. 本检查通过不代表可以直接退款，更不会给关联单批量退款。最终再次读取当前目标售后的状态、金额、SKU和物流证据，保留原90秒物流复查窗口、资金幂等和一次请求保护。

一次读取最多20个 ERP 页（每页30行）、100个不同平台订单，整批取证不超过80秒。超过上限或无法读全即停止放行，不能截断后当作整包裹已核对。老客户历史较多、跨平台/跨店客户或源页面变更可能因此待核实，需要完善源数据访问后再查，不可手动伪造PASS。

## 待办、状态与去重

- 业务阻断：本地订单转“人工处理中”，备注“同包裹仍有订单未申请全额仅退款，已暂停自动退款，请业务员联系客户”。原资金任务保存 `shared_package_check` 完整证据，阻断时没有资金请求。
- 自动创建独立 `ERP_CREATE_MANUAL_TODO`，`origin=module1`、`task_scope=shared_package`。包裹、客户和业务员组成数据库唯一幂等键，避免重复通知；不覆盖原普通待办。外部使用独立“同包裹跟进：平台订单号”标识，保留发送状态、经办人和ERP待办ID。
- 内容只写店铺、要处理的平台订单号、商品型号颜色数量、暂停原因和联系客户要做的事。不发送内部任务号、售后号、退货单号等冗余字段，也不把“拦截指令已发出”说成“快递已确认拦截”。
- 沿用网页“人工待办”发布开关和ERP写开关。关闭时只保存本地待办，**仍阻止退款**。未匹配业务员时不猜人、不发出，等原业务员同步匹配后再发布。
- 该待办不被当前单的平台退款、金额变化或ERP平账顺带取消，因为当前单处理完成不代表包裹内其他订单问题解决。
- 创建业务待办后保持人工锁，后来的有效在途轨迹、其他订单新申请退款、重启、关闭待办开关都不自动解锁。业务员联系客户确认需求后人工处理；本次没有新增无人值守解除人工锁的能力。不可删待办/清空资金任务绕过锁。

技术核验失败不生成“客户未申请”的猜测待办，保存本地失败原因。资金执行器仅把**确定未发起资金请求**的任务交回队列，最早5分钟后重新只读核验（仍受后台周期、物流查询调度和限流约束）。资金请求已开始或结果未知的任务绝不自动重发。

## 查看与只读验收

在工作台“人工待办”查看经办人、原因、具体事项、是否已发送及ERP待办ID；订单详情查看人工处理备注和原退款动作失败说明。完整检查、关联/排除订单及商品证据保存在原资金任务JSON；个案审计只保存在 Git 忽略的 `.runtime/audits/`。

```powershell
.\.venv\Scripts\python.exe -m aftersales_workbench.workflows.shared_package_cli --order-sn 平台订单号
.\.venv\Scripts\python.exe -m pytest tests/test_shared_package.py -q
```

CLI只有只读模式，不创建待办、不发送拦截、不退款、不修改ERP。`PASS`仅表示整包裹保护核验通过，不代表其他资金条件通过、未揽收事实已被证明、仓库验货通过或财务闭环。
