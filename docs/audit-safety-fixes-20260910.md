# 2026-09-10 代码审计安全修复与部署说明

本说明对应审计后的修复分支。修复代码不等于线上已部署或已验收；本批没有执行真实退款、ERP补单、群消息发送、生产数据库迁移或后台重启。

## 已实现的保护

- 平台退款和ERP补单使用独立 `money_operations` 账本。唯一身份为平台、店铺、售后号、操作类型，资金前提交 `REQUEST_STARTED`。ERP模块1/3共用 `ERP_REFUND` 操作类型，平台模块1/2共用 `PLATFORM_REFUND`，不能通过换模块或创建不同任务绕过防重。
- 请求超时、断连或无法确认的响应保留 `UNKNOWN`；请求开始记录、未知记录和已确认记录均禁止重新写入。平台请求回执仅记 `ACKNOWLEDGED`，不等于资金到账或ERP闭环。ERP带副作用GET禁止自动登录后重发。
- PDD空对象、负成功标志不再当成功。天猫客户端要求逐单核验快照，详情身份、金额和商品字段变化阻断；第6店在店铺加载和写客户端双重拒绝，配置不能扩大适配范围。
- 最终资金入口重新核对执行权、平台店铺、模块开关、批准快照、人工状态、物流状态、最近查询错误、90秒时效及工作时间。同步和物流复查不能扩大旧任务批准范围。
- PDD普通在途与特殊分支都检查完整包裹关系。关联查询失败、客户缺失、权限不足、数量不完整不能解释为没有其他订单。
- 102分支拒绝持久化的历史物理轨迹和退回事实；未知非空物流文本默认UNKNOWN。部分退款变化不覆盖等待退回、人工接管及资金操作后的工作流状态。
- PDD发货事实缺失默认UNKNOWN；父订单退款完成不能代替目标售后完成。跨店同售后号先失败关闭，禁止覆写另一店记录。
- 模块2修复不存在的方法调用；ERP明细匹配不再自动生成质检PASS。自动入口将匹配但缺质量证明的单据转人工；资金前核对独立人工质检、最新实收明细、退货运单、ERP退货单和共享包裹关系。
- 人工ERP回填不能直接设置财务闭环；必须由逐单平台/ERP事实核验路径确认。ERP客户字段非空与空反查冲突时，不允许“无需补单”。欠货表头缺失或数量不明均报错。
- PDD/天猫列表计数矛盾、缺列表不能当空结果推进水位；淘宝列表也校验缺字段。合法空结果必须有明确的空结果证据。
- 新增 `parcel_notice_records` 包裹发送凭证，不随任务或JSONL账本删除。粘贴前占用包裹，人工提前发送也补持久化凭证，未知发送结果阻断；不能通过重建同运单任务或清空本地文件重发。
- 企业微信桌面画面变化不再证明消息成功。按发送键后没有消息级回执，保留SendPressed，必须人工核验目标群后使用现有确认入口；后台不自动重发。

## 行为变化和仍未完成的事项

1. **普通在途放款规则等待用户决定。** 本批尚未将现行“有效在途＋成功通知可退款”改为“必须确认拦截成功且退回入库后退款”。独立回归仍保留严格口径断言，不能把该失败当成已修复。
2. **102与双接口无轨迹仍是独立策略。** 历史污染保护已修，但用户列出的14项共同AND条件涉及业务策略变更，须与上一项一并定稿。原业务500无轨迹规则不等于102规则。
3. **天猫自动退款暂时失败关闭。** 当前ERP整包裹来源与平台逐订单关联适配仅PDD；没有假设天猫关联完整。前5店的客户端快照保护已补，第6店硬禁止；前5店自动执行须待整包裹适配与验收完成。能力页反映该限制，不能只显示开关已配置。
4. **ERP质量数据未适配。** 匹配单据须由仓库独立质检；不伪造NORMAL/PASS以保持自动化数量。已有仅“系统ERP核对”生成的PASS不得作为新资金调用的质量证据。
5. **完整复合售后主键迁移尚未完成。** 目前先阻断跨店同号覆盖；原 `after_sales_sn` 全局唯一约束仍在。允许跨平台/跨店同号同时入库，需要另行迁移订单、明细、任务外键及所有查询入口，不能只删唯一索引。
6. **跨包裹唯一实收分配及仓库真实发货锁仍需适配。** 多包裹/同运单多订单的模块2退款继续人工；本地PACKING_LOCKED不代表外部仓库已阻止出库。
7. **“人工已处理”与“确认已发群”的语义等待用户确认。** 本批保留现有ManualHandled业务口径；拟明确区分人工接管和消息已发送，避免互相替代。
8. 每平台每店每阶段的完整授权错误状态、页面展示和安全回补仍需后续完善；本批重点修复异常结构被当空结果的路径。

## 数据库升级与历史隔离

需要先在独立MySQL测试库校验迁移：

- `20260910_0026`：创建资金操作账本。升级前平台RUNNING/FAILED/SUCCEEDED任务记为待核验；旧ERP执行器缺可靠请求前记录，因此非取消的历史ERP资金相关任务先记UNKNOWN，防止升级后误把空账本当成未发送。
- `20260910_0027`：创建包裹发送凭证。历史成功任务只作为LEGACY_SENT防重凭证，不能为新任务证明群消息成功；历史不明确发送保留UNKNOWN。

生产实施前必须准备备份和停机窗口，停止新旧worker并发执行，先迁移数据库再启动对应版本。**本轮仅准备迁移脚本，不执行生产迁移或重启。** 旧ERP任务被隔离后只读核验唯一结果；不能删除账本、改key、换任务或直接设置PENDING来“恢复”。

回退业务代码也必须保留两张账本；迁移的downgrade明确拒绝删除防重证据。


部署后只读查询资金操作，输出包含业务单号，应保留在本地审计目录：
