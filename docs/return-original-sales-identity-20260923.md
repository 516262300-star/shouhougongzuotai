# 原销售部件记法导致的退货误报修复

模块2原先直接拿平台申请SKU与ERP退货商品行比较。平台按成品销售、ERP按把手和底座等部件开单时，完整退回原发货商品也会被误判少退、错退；已退款订单还会错误生成申诉待办。

现在遇到客户名下正式退货单的型号差异时，先只读读取完整客户销售/退货分页，沿退货行关联的内部销售号追溯平台订单。仅在原销售唯一、整单各部件型号颜色数量完全一致、退货单和运单一致、没有其他订单关联冲突或其他包裹重复实收时，转为“实收与本单原销售一致，平台型号记法待核对；非少退错退”。不再生成本次少退/错退失败或退款后申诉待办。

本项只消除“平台成品与ERP部件直接做减法”的错误判定，不建立通用SKU替代关系，不把原销售匹配当作平台映射、独立质检、ERP平账或退款资格通过。真正少退、错颜色、错型号仍按原规则；共享运单继续原整批核验流程。分页不全或查询异常等待重查，不制造失败验货。原自动任务频率、开关、历史待办起点不变。

后台入口为 `Module2ErpIntakeService`，沿用模块2每笔最短30分钟轮询。无需新增环境变量，使用既有ERP只读查询权限。正向核查明细保存在Git忽略的 `.runtime/audits/module2-original-sales.sqlite3`，不向业务员发送测试消息。

历史已发送待办不删除、不重发。本次个案先实时核对平台申请、原销售及完整客户退货账页，再在事务内撤销系统误写的FAIL及DEFECTIVE，保留原结论、实收行和成功发送凭证。验货恢复待独立确认，资金状态不改。真实客户和订单证据仅存受保护的 `.runtime/audits/`。

验证：原销售部件一致、跨订单冲突、数量/型号/颜色差异、重复行、其他包裹、两次读取变化、分页失败、dry-run不写入及不生成FAIL/PASS均有回归覆盖。

发布须读取当前正式主机和Worker指针，从正式源复制候选，仅替换本次两个源文件；测试后持有守护周期锁，等待当前后台自然结束，制作验证备份并做个案事务纠正，再切换Worker指针。不得在已退役机器恢复开关。回退只恢复前一Worker指针，保留个案纠正审计和所有发送/资金凭证；禁止用旧数据库覆盖正式数据来回退。
