# 企业微信窗口尺寸变化导致发送前暂停的修复

## 原因与行为

2026-09-11 晚间，企微窗口缩小后，原先按窗口高度百分比截取的群聊标题区域切掉了文字底部；带窗口边框的截图偏移更明显。Windows OCR 因此漏字或返回空结果，正确目标群被判成群名不匹配。另有输入前临时失焦被当成须手动恢复的暂停。

现在依据原始截图聊天顶部第一行深色文字定位完整标题，裁掉多余背景并补白后识别；高分辨率字形先规范尺寸。只读取第一行，群名仍须完整匹配，不扫描群描述或聊天历史凑结果，不容忍错别字、数字变化或截断标题。

确定尚未输入消息时的前台变化，沿用发送账本的 60 秒冷却重试。后台持发送锁、确认任务仍为 Pending 后重新预检目标群及空输入框。ESC、安全验证、未知异常、已有草稿与相同历史消息仍暂停；已输入或已按发送键的任务不自动重发。发送后只读回执恢复和连续三次消息核验规则保留。

鼠标指针或其桌面高亮覆盖输入区时也可能使空框核验停止；无人值守电脑请将鼠标停在聊天列表空白处，保持企微登录且桌面未锁定。核验无法区分覆盖物与草稿时继续暂停，不能忽略画面中的未知内容。

本机以当前 `monitor-post-refund-worker-20260911` 独立发布副本为基础，复制至 `.runtime/releases/wecom-title-window-20260911`，仅替换 `wecom_receipt.py` 与 `windows_wecom.py`。保留此前模块 2 退款后核账、天猫模块 3 等业务更新，不加载开发目录其他未提交变更。无数据库迁移，无业务开关变更，数据库版本仍为 `20260910_0027`。

发布差异保存于 `deployments/wecom-title-window-20260911.patch`。在上述基础版本副本中先执行 `git apply --check --unidiff-zero`，再执行 `git apply --unidiff-zero` 应用补丁；桌面依赖沿用[消息核验说明](desktop-message-receipt-20260911.md)。

切换前备份 `.runtime/module1-worker-release.json` 和账本，依次执行 `scripts/module1-autostart.ps1 -Action StopWatch`、`scripts/module1-worker.ps1 -Action Stop`，等待后台进程自然退出。调整发布选择配置后执行 Worker `Start`、守护 `StartWatch`。回退采用相同停机顺序，恢复旧选择配置；保留数据库与发送账本，不能删除已发记录。

发送前暂停的历史任务在原因消除后可按已授权范围恢复；`--resume-before-paste ID --limit 1 --apply` 会实际执行发送，并非只修改状态。`PasteStarted` / `SendPressed` 结果不明记录不能这样重试；确认已发送后使用 `--confirm-sent ID --apply` 对账。
