# 天猫同包裹部分订单退款：发群前转人工

## 原因和规则

原整包裹发送保护只覆盖拼多多。天猫普通退款在 `NoticePackageGuard` 中直接通过，多子单合计全额退款路径只验证本交易的全部子单，未查询同客户其他独立交易是否共用运单。因此目标单虽为全额仅退款，仍可能把同包裹其他未退款订单一并通知快递拦截。下游退款步骤的天猫多订单限制不能弥补已经发出的消息。

现对两条天猫桌面发群路径统一先做完整客户包裹核验。目标平台订单查询 ERP 唯一客户及完整原销售分页，再用目标店铺只读授权逐笔查询所有原销售对应的平台交易、运单和退款明细，不以本地售后表只有一笔记录推断包裹只有一笔订单，也不因同客户、同型号就判定同包裹。

- 同客户其他运单经平台证实不同，可以排除；同运单且快递公司一致的交易必须枚举全部子单及退款。只有每笔均为有效全额仅退款，商品、数量、金额和身份完整一致才继续原通知检查。多子单合计全额交易还需通过原交易级复核。
- 明确存在未申请退款、部分金额/数量、撤销或拒绝、退货退款等情形，取消同运单和快递公司的未发送通知，转同包裹人工待办。按退款申请对应原销售订单的业务员分派，同一业务员合并；跨业务员分别跟进。原已发送、已输入或结果不明凭证不得改成未发送。
- ERP 分页、店铺授权、平台身份、运单、明细或状态无法核实，跨店/跨客户关联未覆盖，多包裹或过期证据，均不发群；保留待核验原因及五分钟冷却，下轮自动只读重查，不伪造已转业务员或未退款结论。
- 保留原80秒证据时效、输入前快照与人工锁检查、目标群白名单和永久包裹防重。人工锁不能因客户后来又申请退款而自动解除。

入口仍为 Module1 原通知阶段和原桌面守护，无新增任务、开关、数据库迁移或资金权限。此功能只保护快递拦截，不建立多订单退货实收自动分配，不扩大无人值守退款范围。已退款事实及既有退货核账流程保留。

## 已发消息的个案处理

历史误发不能当作未发送，也不能声称已经撤销快递拦截。经完整客户和实时平台核验后，通过原待办发布器补充人工跟进，明确列出运单与关联未退款订单，要求业务员核实快递执行情况，并在其他订单仍需收货时协调撤销整包裹拦截。已退款订单提醒勿重复退款。沿用原业务员复核、远端查重与回查，不重发快递群通知，不自动发送撤销指令。

个案订单、客户、运单及证据只保存在 Git 忽略的 `.runtime/audits/tmall-shared-notice-20260921/`。不删除历史资金、消息或待办记录。
