# 天猫模块1退回核账状态纠正

用户要求开启“模块1·退回平账”。检查发现该能力不能用一个布尔状态概括：现有后台已经执行天猫退货归属及既有退款流水核账，而自动认领暂存单、缺退款单时自动补单尚未适配。此前页面统一显示“未接入”以及交付中“天猫退回平账都未接入”的表述不准确。

## 实际运行边界

- `ErpReturnMatchSyncService` 已在既有 worker 中按 `ERP_RETURN_MATCH_BATCH_SIZE` 和 `ERP_RETURN_MATCH_REFRESH_SECONDS` 周期查询；`ERP_RETURN_MATCH_SYNC_ENABLED=true` 时，核查退货在客户名下、在暂存列表、未找到、明细不符及应收情况。
- 天猫 `verify_closure` 使用 `inspect_settled_tmall_refund` 核实对应原收款、退款流水、金额、无欠货及零应收；只有退货明细和闭环证据一致才更新本地完成状态，不把余额为零当成独立的闭环证据。
- `STAGED` 保持“退货单在暂存列表，等待认领”；没有自动认领。已入客户名下但应收未归零继续待处理，没有为天猫开放ERP自动补单。现有 `Module1ErpRefundService` 及资金闸门对非拼多多补单的限制保持不变。
- 核账是只读ERP业务，不依赖天猫退款子账号或ERP资金写开关。页面不因珂琪艺、适家缺少退款写权限而把已运行的核账显示为未开启。平台退款权限、核账、认领、补单是独立能力。

## 本次变更

能力接口的天猫 `module1_erp` 按真实只读查询条件显示：同步、ERP核对及查询凭据具备时，显示警示状态“核账已开·认领补单未接入”；任何必要条件缺失时显示未开启及原因。该警示状态不计入“模块全开”。前端已有警示样式与详情说明，不重建前端。

本次只更新Web能力状态，不修改 `.env`、业务worker、资金账本、业务任务或ERP数据，不开启模块3，不放宽多订单/多包裹核验或人工锁。

只读数据库核对时，天猫退货匹配任务有2条 `closed_loop/SUCCEEDED` 且保存闭环证据；其余15条为11条未找到退货、3条待核验退款流水、1条应收未归零。此为已有系统记录，不声称由本次新处理或本次重新实单验收。运行日志显示退回匹配阶段持续完成。
