# 企微历史消息回执复核

## 故障与修复

2026-09-22发现一条拦截通知在按发送键后，两次观察都识别到正确群、完整自身消息、空输入框和正常发送状态；随后群中新消息使原消息移出可见区域，未达到连续三次确认。旧自动复核只读取当前画面，消息不可见时会长期保持 `SendPressed` 并阻止后续发送。机器人回复或出现相同运单文字不是完整自身发送凭证，不能据此直接标成功。

`WindowsWeComGateway.verify_existing_receipt` 现允许在同一目标群内有限向上滚动回看。仍由原Worker在原桌面发送锁内调用，不增加定时任务、环境变量、店铺权限或资金权限。

- 每次回看前核对当前完整群名、空输入框及发送状态；至少两次观察、跨度两秒确认目标消息不可见后才尝试滚动。滚动前再读一次完整画面，核对前台窗口、进程、安全验证、ESC和窗口尺寸。
- 只向已定位的聊天正文区域分三次各发送一格向上滚轮，保留画面重叠；不点击、搜索、输入、粘贴或按发送键。每格入队后等待170—260毫秒派发，再仅在鼠标仍停留于程序定位处时恢复之前鼠标位置，避免滚轮落到原鼠标位置或覆盖用户正在移动的鼠标。每格前重新核对前台、ESC和鼠标位置；用户移动鼠标时停止剩余滚动。分步发送避免企微把单个大滚轮增量只处理成一步。
- 每轮最多八次回看、正常预算90秒。原一次失焦恢复仍受原窗口/进程保护，恢复后重新核验。超时、错误群、草稿、安全验证、多个匹配气泡或发送异常时保持暂停，不猜测成功。
- 找到原消息后必须重新获得连续三次完整核验，跨度至少两秒；滚动前旧观察不拼接成成功证据。运单及正文精确匹配、群名白名单、自身气泡、发送状态要求保持。
- 实时证据落盘后，原恢复器复核动作、运单、群名、计划哈希和包裹账本，才完成原任务并解除阻塞。发送次数不增加，不重置账本重发，不执行退款。首次正常发送后的45秒观察保持原行为。

审计沿用 `.runtime/audits/desktop-receipts/`，增加回看次数及逐次滚动事件；恢复记录仍在 `.runtime/audits/desktop-receipt-recovery/`。当前群不是目标群、消息超出回看范围等情况继续待核实，不会自行搜索或切换到其他群。现场订单、运单、群聊截图和部署证据只放Git忽略的 `.runtime/audits/intercept-failure-20260922/`。

每轮有限回看结束仍未找到时，原恢复器保留发送凭证并安排60秒冷却，下一正常通知周期继续只读核验；不是60秒后强制重发。未切换目标群时，下一轮从当前历史位置继续，实际间隔还受后台业务周期耗时影响。群名不符、用户停止或安全验证不会被绕过。
