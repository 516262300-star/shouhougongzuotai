# 售后订单 ERP 归属与抖音实付资料修复

2026-09-30。

ERP 归属查询已核对客户身份，销售页明确显示“当前没有单据”、页码为 1/0 且无商品行时，记为 `sales_not_found`，售后订单显示“ERP 暂无销售记录”。客户销售记录完整分页核验后，若没有当前订单，也使用同一状态。提示明确限定“未查到该订单的销售记录”，不把客户的其他销售误算成本单。这不是查询失败，不代表未发货、可退款或已平账。归属后台沿用常规复查周期；网络、身份、分页或商品行异常仍保留失败重查。此空页识别仅用于限定目标订单的归属查询，不放宽整包裹、实收数量或资金核验。

抖音售后列表不保证提供父订单买家实付。同步现在通过只读 `/order/orderDetail` 读取 `data.shop_order_detail.pay_amount`，验证订单号及店铺 ID 完全一致，并将非负整数分换算为元后写入 `platform_order_amount`。一个同步窗口内，同一父订单只读一次。不得使用申请退款、实退、子售后商品小计或商家应收替代买家实付。

订单详情不可读、身份不符或金额无效时，该同步窗口失败并回滚，不推进游标、不把已有实付清空。连接恢复后后台按原窗口重查，只调用读取接口。未新增自动退款权限、队列任务或资金重试。

历史资料回填按店铺及父订单分组，先取得平台证据，再仅补仍为空的实付；ERP 仅更新已经重新核实的归属缓存。保留业务 `updated_at`、退款状态、资金流水和工作流状态。并发时重查原值，不能覆盖已被其他运行器更新的资料。订单标识、原值、响应证据和结果放在 Git 忽略的 `.runtime/audits/order-data-repair-20260930/`，不上传远端。

验证覆盖空销售页与错误页面的区分、客户身份、包裹核验不放宽、缓存复查周期、父订单/店铺身份、分元换算、无效金额、多个售后共享父订单查询，以及既有 ERP、抖音和平台同步回归。正式环境采用各自现行版本作为网页及后台基线，保留桌面登录和已上线的其他功能；网页仅增加新归属状态的展示文案。

发布及恢复：核对当前 release 指针与基线摘要，生成独立候选目录；请求后台自然结束当前周期后切换指针，通过现有守护计划任务恢复运行。验收 `/health/ready`、后台新周期及售后订单接口。回退使用审计保存的原始 release 指针，仍须自然停止后台；已核实的只读资料无需随代码回退抹除。
