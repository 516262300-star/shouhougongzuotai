# 发货20小时无物流信息提醒

2026-09-19 用户授权：拼多多、天猫订单发货满20小时仍无物流信息，向对应业务员发布原管理系统人工待办。20小时为固定业务规则，相对发货后24小时提前4小时；不是平台违规判定，也不覆盖可能更早的订单承诺时限。

## 范围与判断

- 使用拼多多 `pdd.order.number.list.increment.get`、天猫 `taobao.trades.sold.increment.get` 同步普通订单，不要求订单申请售后。首次回溯最近72小时的订单修改记录，之后按独立游标持续增量；不承诺覆盖启用前72小时外且此后未变化的历史订单。
- 从平台订单详情读取真实发货时间，满20小时（含）后查物流。已超过24小时的漏提醒订单也补入，并写明已超24小时。
- 物流来源复用快递100。只接受已校验的正常“查询无结果”业务响应；网络超时、鉴权失败、身份不符、解析失败或不明空响应保留本地错误并重查，不发送无物流提醒。已有任何轨迹（包括下单/待揽收轨迹）不符合本次“无物流信息”规则；曾观察到轨迹后不因后来空响应重新提醒。
- 天猫逐包裹查询。多包裹须能唯一关联子订单发货时间，否则保留核验错误，不借用另一包裹的发货时间。拼多多以订单详情返回的原发货运单为监控对象。
- 平台订单关闭、已签收、全额退款完成或包裹信息变化时，发布前重新判定。提醒不调用退款、拦截或ERP资金操作。
- 业务员从ERP原发货销售订单读取；归属缺失、冲突、查询失败保留本地待办，恢复后重查。不使用客户档案归属兜底。

## 发布、防重及查看

待办文字包含店铺、平台订单、运单、发货时间、剩余时间/已超时和“联系仓库或快递核实交运、催促实际揽收并回传轨迹”。业务员在原管理系统待办事项查看。本次新增普通订单账本独立于现有售后人工待办页面，尚未合并进该页面。

同店铺、同订单、同快递公司及运单只发布一次，业务员变化不重发。发布前复核订单、物流和网页人工待办总开关；请求之前写入 `SUBMITTING`，断线、超时、崩溃或保存结果不明保留 `UNKNOWN`，后续仅回查原待办，不自动重新提交。查询确认存在才标记 `SENT`。不要删除账本恢复发送。

继续遵守 `ERP_WRITE_ENABLED` 和网页“人工待办自动发布”开关；关闭后仍可同步及保留本地待办。这个独立提醒是用户新授权的规则，不修改原售后“连续无轨迹不发给业务员”的分流规则。

## 运行、配置与恢复

入口：`python -m aftersales_workbench.workflows.shipment_watch_cli`。不带 `--publish` 只进行平台/物流/ERP归属只读查询及本地记账；带 `--publish` 才尝试发布。`--status` 只读取游标、数量和错误；`--max-windows` 控制每店追赶窗口数，`--limit` 控制单轮核验数。拼多多窗口28分钟加2分钟重叠，天猫窗口20小时加2分钟重叠，均完整分页后才推进。

沿用已有拼多多七店、天猫六店、快递100与ERP凭据，无需新增密钥。正式运行机独立发布指针 `.runtime/shipment-watch-release.json` 需要 `enabled: true` 及限定在 `.runtime/releases/<版本>/src` 的 `source_path`。开发机不启用。

```powershell
# 先完成数据库迁移20260919_0029及正式只读预演，再安装
.\scripts\shipment-watch-task.ps1 -Action Install
.\scripts\shipment-watch-task.ps1 -Action Status
# 停用后当前周期正常结束；立即禁止新发布可关闭网页人工待办开关
.\scripts\shipment-watch-task.ps1 -Action Disable
```

计划任务 `Leedis Shipment No Trace Reminder` 每5分钟触发，复用正式守护账户的登录身份，通过 `pythonw.exe` 无窗口运行。运行中不启动第二份实例，数据库命名锁也禁止跨进程/机器并发。单轮平台限流、追赶积压或接口耗时会延后提醒，不能承诺精确到20小时整。

运行输出：`.runtime/shipment-watch.log`、`shipment-watch-status.json`、`shipment-watch-error.log`。`lagging_shops` 表示增量落后超过10分钟；`sync_errors`、`order_errors` 必须处理，不能当作无待办。首次72小时回溯完成前不代表覆盖已追平。

数据库新增 `shipment_watch_cursors`、`shipment_watch_orders`、`shipment_no_trace_notices` 三张表；原数据库完整备份自动包含这些表。备份及代码打包脚本同时保存独立发布指针和对应代码；迁移恢复必须保留这三张表及原待办ID。回退只关闭独立任务或指向兼容代码，不删表、不清游标、不覆盖业务数据。
