# 企业微信发送后自动核验（2026-09-11）

## 修复的原因

此前发送网关在按下发送键并检测画面变化之后，无条件抛出“缺少消息级成功回执”，所以真实发群成功也会永久停留在 `SendPressed`。前台激活失败的60秒重试只处理输入前失败，不能解决此问题。

本次使用本机 Windows 中文 OCR 读取群标题，使用离线 RapidOCR 模型读取草稿和消息气泡。正文、完整运单号必须逐字匹配；仅规范化空格和标点，不模糊匹配字母、数字或中文。群标题只允许空格与短横线/中点等分隔符的识别差异。低于0.95的正文行识别置信度不通过。所有识别在本机内存完成，不调用云端识别接口，关闭 ONNX Runtime 诊断遥测。

发送步骤：

1. 搜索后读取完整目标群名，确认输入框为空，当前消息区没有相同的已发气泡。
2. 写入 `PasteStarted` 后输入消息，回读完整草稿并再次核对目标群名；不一致则停止，不按发送键。
3. 写入 `SendPressed` 后仅按一次发送键，等待界面更新，再最多核验12秒。
4. 至少三次观测、跨越至少两秒，同时满足正确群名、空输入框、一个完整匹配的右侧蓝色气泡，以及气泡左侧没有红色失败或灰色等待标记，才执行 `hooks.sent()`，同步本地账本、数据库包裹账本与任务状态。
5. 不满足时保持结果不明，显示连续核验失败提示，禁止自动重发。OCR组件、窗口或布局无法识别也不会当作成功。

发送后的短暂失焦允许一次仅用于读取回执的原窗口恢复；普通失败时也可回到工作页面，但不据此确认消息成功。ESC/安全验证仍冻结所有操作。具体边界和历史已发任务对账见 [发送后失焦复核与原窗口恢复](desktop-focus-recovery-20260911.md)。

这是对企业微信客户端已发消息状态的自动核验，不是企微服务器提供的投递回执，更不代表快递员已读、已同意拦截或包裹已经退回。原有物流及资金规则保持不变。现阶段支持已验证的浅色聊天界面、成员栏展开或收起及常见窗口缩放；其他主题或布局无法识别时暂停。桌面应保持登录、未锁屏，发送期间避免切窗口。

历史遗留 `PasteStarted` / `SendPressed` 不因升级而自动清除、重发或伪造成功。核实已发后仍使用 `--confirm-sent` 对账；新流程通过自动核验的消息无需再逐笔人工确认。该方法也不会自动采纳群内机器人或其他人的回复作为本账号发送凭据。

## 依赖与部署

从本仓库安装桌面额外依赖：`.venv\Scripts\python.exe -m pip install -e ".[desktop]"`。包含 Pillow、RapidOCR ONNX Runtime 1.4.4 与 PyWinRT 3.2.1 对应模块；Windows须具备简体中文OCR。模型随识别包安装，运行时不上传聊天截图。该额外依赖不要求修改系统权限或重新登录企微。

本机以 `.runtime/releases/safety-erp-outstanding-final-20260911` 为基础，复制为 `.runtime/releases/message-receipt-20260911`，仅更新企微网关、新增 `wecom_receipt.py` 和桌面依赖清单，不加载开发目录的其他未提交业务变更。`deployments/desktop-message-receipt-20260911.patch` 保存相同的发布差异；重建时在原发布副本执行 `git apply --check --unidiff-zero` 后使用 `git apply --unidiff-zero` 应用补丁，安装桌面依赖并运行相关测试。

切换前备份 `.runtime/module1-worker-release.json`、发送账本及日志，停止守护，等待后台当前周期自然结束，再调整选择配置并启动后台和守护。保持数据库迁移版本 `20260910_0027`；本次没有数据库迁移，也不改退款、ERP写入、批量发送或水位开关。回退同样先安全停机，恢复旧选择配置；保留所有账本，不删除记录来恢复发送。
