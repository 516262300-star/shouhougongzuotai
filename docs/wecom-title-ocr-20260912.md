# 办公室运行机企微群名识别修复

## 现象与原因

自动拦截任务已进入正确快递群，但在输入前报“群聊标题未匹配目标完整群名”。实际完整标题裁剪正确；Windows OCR 在该机器的紧凑粗体标题两端额外识别出标点，导致白名单严格比较失败。原发送器在输入前暂停是正确的保护行为。

## 修复

`LocalReceiptOcr.read_title` 优先使用现有 RapidOCR 对同一完整首行标题裁剪进行识别，继续要求每条识别置信度不低于 0.95；无法获得高置信度文字时才使用 Windows OCR。高置信度结果即使不匹配目标也不切换引擎寻找匹配结果。

完整群名比较、标题范围和裁剪边界保护保持启用，不删除 OCR 多余文字、不做模糊匹配，也不扫描群说明或聊天记录来凑白名单。草稿、完整消息、发送回执和防重复账本的规则保持启用。

## 验证与上线

51 项群名/回执、发送器及恢复服务测试通过。实际故障画面离线重放后，正确完整群名通过，相同名称加一个字和其他群名均拒绝；输入框确认为空。真实截图及订单证据仅保存在 Git 忽略的 `.runtime/audits/`。

上线时先暂停新机守护并等待 Worker 安全退出，基于新机当时正在使用的版本复制新发布目录，只替换标题识别文件，保留已上线的资金结果确认代码。验证候选版本后切换发布指针并恢复实际桌面会话守护；失败可回退原代码指针，不覆盖数据库或发送账本。

若失败任务已由人工在正确群发送且快递方明确确认同一运单，先留存证据并走既有人工确认回写流程，避免修复后重复发送。未确认的输入或发送结果仍保留阻塞，不用清空账本恢复。
