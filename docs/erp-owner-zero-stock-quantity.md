# ERP 入库化只为零时的原销售归属查询

2026-09-30。

客户“发货销售单”表的件数、盒每件、只每盒和入库化只是不同字段。已观察到前三列均为 1、入库化只及金额为 0，且同一 ERP 订单已有退款收款记录的情形。不能概括成“所有数量为零”或据此认定 ERP 原始资料错误；现有证据也不能单独证明零值的形成原因。归属查询不得用前三列乘积替换入库化只，更不能回写 ERP 数量。

原销售业务员识别与商品数量核验分开：仅在 `only_order=True, for_owner_lookup=True` 时，完整读取全部销售分页、核实客户身份、精确平台订单号和销售关联 ID 后，允许目标原销售商品行的入库化只全部为零，按全部行的唯一非空业务员返回 `matched`。原始零数量保留，冲突或缺失的业务员不能忽略；非法数量、负数、非有限值、非法销售 ID、身份不符、分页不全仍不能匹配。

归属匹配只供售后展示及负责人分配，不证明已发货、仓库实收、可退款或 ERP 平账。整包裹及资金核验默认调用继续逐行要求正数，不启用归属查询模式。本次不修改 ERP 单据、实收、资金记录或退款状态。

归属同步仍由既有后台及复查周期执行，无新增计划任务、环境变量或自动化权限。个案只读重新核实后，仅更新归属缓存，并保留业务时间和退款字段。订单标识、客户资料、原网页、缓存前后值及发布摘要仅保存到 Git 忽略的 `.runtime/audits/erp-sales-quantity-20260930/`。

发布从正式后台当前版本复制，只更新原销售读取与归属说明两个文件。相关测试通过后请求旧后台自然结束当前周期，由现有守护任务启动新版本；核对售后列表接口、健康检查和新进程。回退使用私有审计保存的原 release 指针，同样等待当前周期自然结束。
