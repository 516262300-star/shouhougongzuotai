# 异常明细与运行监控分离

## 使用入口

- **异常明细**：独立左侧主导航。按未解决、人工跟进、已恢复、已停止或全部历史查询；
  保留平台、店铺、异常类型与关键词筛选、分页、处理建议、变化记录和精确查看订单。
- **运行监控**：查看运行器、最近完整周期、发送队列、模块开关和阶段执行统计。
  阶段状态为 `failed` 才显示失败原因与“查看失败明细”；点击后进入独立异常页，
  仍按该阶段、周期和可核实来源定位，不把所有历史问题混作本轮失败。
- 在定位页点“查看全部异常”，或重新点击左侧“异常明细”，恢复普通异常查询。

订单异常与模块执行失败分开表达：拼多多同步阶段为 `warning` 或 `acknowledged`，
且明确 `shops_failed=0` 时，表示普通订单同步已完成、个别异常单仍隔离重查；
运行监控按执行完成展示，独立异常页保留订单的真实未解决/人工跟进状态与原始原因。
缺少失败店铺统计、整店失败、未知状态、发送阻断不改写成正常。
普通业务异常数量和人工跟进文案不再嵌入模块行；扫描、新增、已执行等运行统计保留。

## 运行与发布

沿用现有 `/api/v1/monitor/status` 与 `/api/v1/monitor/issues`，15秒刷新频率不变。
不修改 worker、同步隔离、退避重查、退款权限、资金记录或待办发布规则。
人工知悉入口沿用本机同源与版本校验；独立页面不会自动提交处置操作。

本次只更新本机已有 web 发布目录的前端静态产物。发布前将 `index.html` 与
`.runtime/workbench-web-release.json` 备份到 `.runtime/backups/monitor-navigation-<时间>/`，
补齐新资源后替换入口，保留旧资源；更新指针中的前端版本及入口哈希。
无需重启 worker 或 web，刷新浏览器即可加载。回滚时恢复两份备份文件。
既有其他未提交功能不随本次发布。前端的 Sites 兼容包装保留，不发布业务数据到云端。

## 验证

验证独立导航、模块页移除异常表、失败入口保留精准来源、人工跟进可见及恢复后退出定位，
并检查隔离同步不等同于执行失败、真实失败/未知状态不被改成正常。
前端构建与 Sites 包装检查沿用现有项目命令；监控回归使用独立临时测试目录。

构建命令生成相同前端与兼容包装产物，未修改依赖。
