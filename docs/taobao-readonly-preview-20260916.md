## 使用方法与边界

入口：`aftersales_workbench.workflows.taobao_preview_cli`。手动运行，不挂计划任务或常驻Worker，不新增配置开关，不提供 `--apply`。

```powershell
# 在已配置正式凭证的运行环境中，PYTHONPATH须指向经过验证的独立候选src。
python -m aftersales_workbench.workflows.taobao_preview_cli --limit 3
# 内部ID，不是平台订单号；可重复指定，最多10条。
python -m aftersales_workbench.workflows.taobao_preview_cli --order-id <工作台内部ID>
```

默认查询最近30天记录，按工作台内部ID倒序，最多3条；`--limit`最多10条。定点内部ID不受30天条件限制。依赖现有 `TAOBAO_SHOPS_JSON`、淘宝网关/请求方式、ERP网页登录配置、数据库URL；凭证不进入日志或文档。同步停用环境拒绝运行；最近30分钟无无错误成功同步亦拒绝。

数据库要求MySQL，并开启 `SET TRANSACTION READ ONLY`、禁用自动flush、结束回滚。没有本地数据库时不得启动第二套数据库/自动化来预演。读事务不构成并发资金锁或持久化授权；预演结果不能用于随后直接执行资金写入。

平台客户端只允许5个指定查询方法，资金及通用方法调用均拒绝；单个查询不自动重试。ERP HTTP额外限定同源和指定只读路径，仅登录POST例外；禁止退货搬单、草稿写入、deleteprodlist及showlist。页面登录重定向不能跳到其他域名。

## 已适配的证据层

| 模块 | 只读覆盖 | 未完成的执行验收 |
| --- | --- | --- |
| 1：已发货仅退款/退回平账 | 实时卖家、售后、单包裹与原销售；退款已成功时检查正式退货或暂存，以及客户退款流水/余额 | 拦截与物流退款闸门、认领占用、ERP补单、资金执行 |
| 2：退货退款 | 单SKU全额申请、原销售、正式TH或暂存单唯一实收明细 | 独立质检、实收占用、认领、退款写入与结果确认 |
| 3：未发货平账 | 明确平台退款成功、无发货事实、淘宝旧ERP管理详情/账页、SKU欠货、原收款及退款流水 | ERP资金补单执行和幂等验收 |

淘宝使用自身店铺身份与 `tbx` 前缀，不借用天猫专用接口、天猫退款凭证或天猫资金开关。共享只读ERP辅助函数保留原天猫默认行为；资金服务白名单不扩淘宝。

首期仅覆盖单客户独立订单、单子单、单SKU、单包裹、全额等额场景。多销售记录、多售后共用订单/运单、优惠/运费/部分退款、缺失SKU、历史执行、资金账本、人工锁、异常同步记录均拒绝自动建议。复杂场景按[多订单多包裹核验规则](customer-multi-parcel-return-verification.md)整批人工核验，不关闭全局防重。

`preview_evidence_only` 仅表示本次部分证据核验完成；`execution_ready` 恒为false，`refund_permission`、`warehouse_qc` 恒为 `not_verified`。内部ERP返回的ready/completed只作为只读账页证据，不修改业务闭环状态，也不宣称由工作台完成。
