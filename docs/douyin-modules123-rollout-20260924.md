## 自动执行范围

| 模块 | 可自动处理 | 继续保留的边界 |
| --- | --- | --- |
| 1 在途拦截 | 独立客户全部商品账页、完整父单及唯一发货包裹均核实后入通知队列；实际发送仍需物流预检与输入前复核。真实TH退回、原收款及退款金额一致后执行专用API，平台成功后核账补单 | 不采用拼多多无轨迹风险规则；不在派件/已签收时新发拦截；首期不在仓库收到前放款；退款遵守模块1工作时段 |
| 2 仓库验货 | 客户名下正式TH与原销售逐项匹配、完整型号颜色数量及独立仓库质检PASS均一致，实时状态11允许时单次退款；已退款的仅补单核账 | 开TH/型号一致不代替质检。暂存认领、多订单/多包裹、部分商品退款、交叉运单仍须人工，不能宣称全自动认领 |
| 3 未发货 | 实时平台证明未发货、独立整单全额退款成功，ERP原收款/订单/SKU一致时单次补开退款单 | 不执行未发货平台退款；多子单、金额差异、原单/原收款缺失保留，绝不抹差 |

独立退回首期仅接受客户完整单页（最多30行）、一笔商品原销售和可唯一归属的税点，退货最多一张TH。超过此范围不是“未退回”或“客户错退”，只是该自动适配器不能作出完整判断，转客户整批人工核验，遵循 [多订单、多包裹核验规范](customer-multi-parcel-return-verification.md)。

## 金额、资金与防重

- 订单父单实付、商品子单实付、申请和本地金额必须精确一致，不把“商家收入”冒充买家实付。
- TH商品与税点分别追溯原销售、核对负数数量及显示单价镜像；精确金额来自原SK收款和平台。页面单价经显示舍入，不能用“显示单价×数量+税点”强行抹差。
- 使用独立 `/afterSale/operate` 资金客户端，退款操作码111（退货退款）/201（已发货仅退款）；带平台最新 `update_time`，不发送 `remark`，不发送任何平台留言。同步客户端写业务白名单不放宽。
- 实收SKU分配键兼容此前人工单笔验收，另加整张TH唯一占用；与资金 `MoneyOperation` 持久化记录共同防重复。已发起、超时、结果未知不自动重发，只读回查。
- 协议成功/受理不等于退款完成。只有平台实际退款金额和完成时间核实后才能ERP补单；补单必须读到对应唯一负数SK、无欠货及零应收才记闭环。
- 不创建虚构仓库收货或质检记录，不自动清除争议、人工待办或已占用记录。拼多多通用物流及退回任务不消费抖音专用资金任务。

## 配置与运行

独立开关 `DOUYIN_MODULE1_ENABLED`、`DOUYIN_MODULE2_ENABLED`、`DOUYIN_REFUND_EXECUTION_ENABLED`、`DOUYIN_MODULE3_ENABLED` 默认全部关闭。分别配置 `DOUYIN_MODULE12_SHOP_CODES`、`DOUYIN_MODULE3_SHOP_CODES` 为四店白名单。

本次授权积压纳入水位为 `DOUYIN_MODULE12_MIN_ORDER_ID=0`、`DOUYIN_MODULE3_MIN_ORDER_ID=0`；这只允许扫描既有记录，不解除历史状态/异常锁。每周期仅消费当周期同步成功的店铺，金额和状态仍实时查询。模块1/2每批最多20笔，异常每30分钟复查，使用独立轮询进度在数据库LIMIT前排除未到期项，避免同一旧单持续占据批次。模块3沿用既有 `MODULE3_WORKER_BATCH_LIMIT` 和公平轮询，按平台独立分配；本次核实正式值仍为1，即抖音每周期最多检查1笔，本次未调整这一全平台共用额度。既有积压会逐轮纳入，但当前吞吐量不能保证及时清空，批量调优应单独评估，不可写成已全量处理。

ERP补单另受 `ERP_WRITE_ENABLED`、退回补单总开关 `MODULE1_ERP_REFUND_EXECUTION_ENABLED`、模块3总开关 `MODULE3_WORKER_ENABLED`/`MODULE3_ERP_REFUND_EXECUTION_ENABLED` 保护；模块2须 `MODULE2_WORKER_ENABLED`。本次不会为抖音调整其他平台总开关。

仅只读验收命令（仍须设置正确正式运行目录、数据库及专用店铺范围）：

```powershell
python -m aftersales_workbench.workflows.douyin_module12_cli --limit 20 --details
python -m aftersales_workbench.workflows.module3_erp_refund_cli --platform DOUYIN --limit 20 --details
```

不得把历史个案 `--apply` 脚本当通用命令。后台开启后禁止另开并行手工批处理。关闭时先关抖音专用开关、由守护停标等待周期安全结束，不强杀资金请求、不清除资金账本。回滚代码不能回滚或删除已产生的资金记录。
