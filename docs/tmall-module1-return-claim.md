# 天猫模块1：暂存认领与ERP补单

## 范围与运行入口

2026-09-11 接入现有ERP网页业务入口，不需要新的ERP服务器接口。用户已确认现有ERP登录账号仅供工作台自动化使用。平台已成功退款后，本功能处理ERP退回归属及账务，不再调用平台同意退款。

首期限定天猫第1至第5店、现有模块接入水位之后的已发货仅退款。第6店适家保持只读核账。资格依赖主账号的实时售后查询及卖家身份验证，与子账号的平台退款写权限分别判断。

- 单客户独立订单、单子单、单原销售、单包裹、单张TH单唯一商品行。
- 平台申请金额、实际退款成功金额及本期适配的整单金额口径一致；ERP原销售价格×数量、唯一原收款也须等额。优惠差额、运费折算或价格缺失不猜测。
- 客户原销售/退货账页必须完整单页且不多于30行。暂存列表完整读取，最多20页，每页500行，回读首页检测变化。
- 完整型号、颜色、实收数量、原价、运单与唯一原销售对应。暂存已有的正价格必须等于原价；自动化不把0价或未知价改成估算价。
- 同TH多行、多订单、多包裹、其他收退款流水、有欠货、草稿冲突、共享包裹人工锁均阻断。不会建立虚构一对一收货或仓库质检记录。

后台沿用 `module1_worker` 的 ERP 阶段。`TMALL_MODULE1_RETURN_CLAIM_ENABLED=true`、`ERP_AUTOMATION_ACCOUNT_DEDICATED=true`、`MODULE1_ERP_REFUND_EXECUTION_ENABLED=true`、`ERP_WRITE_ENABLED=true` 及天猫同步/模块、ERP查询/核账开关都满足时执行。默认模板保持关闭，未改变拼多多流程或天猫模块3开关。

独立预检命令（默认不修改生产订单，不发送认领或资金请求）：

```powershell
.venv/Scripts/python.exe -m aftersales_workbench.workflows.tmall_module1_return_cli --limit 5
```

可用 `--order <平台订单号>` 限定一笔。`--apply` 才执行，并仍受以上开关和全部校验限制。不要使用历史个案订单号作为批量执行模板。

## 步骤与完成口径

1. 实时查询平台与ERP，确定客户和原实收；检查账号未保存单据为空。
2. 占用整张TH单和专用账号，发出一次搬单请求。同时回查精确草稿和暂存原单消失，部分搬单不能继续。
3. 下一轮重新核验后，用草稿原字段填写目标客户，不新造TH单号，不改型号、颜色或实收数量；回查客户归属。
4. 再次核验后发出一次保存请求。草稿消失只登记 `awaiting_posting`，不表示归属或平账完成。
5. 后续回查原TH单正式进入目标客户名下，且原销售ID、运单、明细、价格一致，才结束认领占用。
6. 确认平台退款成功、正式退货、唯一原收款、没有本笔退款流水、无欠货，且应收为本笔负金额后，用现有ERP补单入口发送一次请求。
7. 重新查询对应SK退款流水和零应收，再由原闭环核验器登记闭环。不以HTTP响应或列表消失冒充平账完成。

任务详情保存 `erp_return_claim_status`、最近检查时间及阻断原因。状态包括 `draft_moved`、`draft_assigned`、`awaiting_posting`、`claimed`、`completed`、`blocked`。店铺能力显示“有限开启·认领补单”表示后台已接入限定范围，不表示每个订单已完成或已通过真实资金验收。

## 幂等、断电与恢复

- `.runtime/erp-return-claims.sqlite3` 持久化整TH单、账号占用、批准明细和 `MOVE / ASSIGN / SAVE` 请求状态。操作系统文件锁避免本机同账号并发；进程退出释放执行锁，但不删除业务占用。
- 每次只发送一个认领写步骤，先提交 `REQUEST_STARTED`，再发送请求。异常记 `UNKNOWN`；下轮只读回查旧步骤，不能重发。结果未核实时账号持续占用，其他单不能混入草稿。
- ERP补单仍使用数据库 `money_operations` 的统一 `ERP_REFUND` 唯一键，模块1与模块3不能重复退款；资金请求禁止自动重试或跟随重定向。超时只能回查，不能清空账本重跑。
- 不自动清理陌生草稿、不自动撤销或作废原单、不解除历史人工锁。卡住时先停该功能开关，核查正式退货、暂存和未保存单据以及已有请求记录，禁止删除账本来恢复。
- 发布副本必须共用持久化项目 `.runtime`，不能把账本放在随发布删除的代码目录。只支持当前本机单一专用ERP账号，不支持多台机器共享该账号同时写入。
- 个案明细含客户/运单资料，仅保留在Git忽略的运行目录和业务数据库，不上传GitHub。

## 验证说明

离线测试使用合成订单与模拟ERP，覆盖草稿冲突、跨订单占用、部分搬单、超时恢复、保存不等于入账、原销售/SKU/价格差异、资金账本先提交、ERP资金未知后不重发及店铺/专用账号开关。

真实只读检查已确认现有账号可读取暂存列表，未保存草稿为空。抽查的待处理订单存在金额口径差异或同客户多订单，按规则阻断，未用于真实认领或资金写入验收。不能把历史“已闭环”记录算成本功能此次完成的业务。
