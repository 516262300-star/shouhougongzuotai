# 企微发送后失焦复核与原窗口恢复

本次只修改桌面发送网关，不调整退款、ERP 补单、物流规则、群映射、后台频率或任务水位。原发送前严格核对群名、空输入框、完整草稿和防重记录均保留。

## 使用行为

1. 记录发送前的工作窗口，按原流程输入消息并只按一次发送键。
2. 发送后的消息核验期间，如果前台短暂变成其他程序，最多恢复**同一个窗口、同一个企微进程**一次，仅用于读消息。不重新搜索群，不输入/粘贴，不再按发送键。
3. 恢复后丢弃失焦前的观测，重新进行最多 12 秒的连续核验；完整群名、完整正文、空输入框、唯一匹配的本账号气泡及无失败/等待标记等条件不放宽。至少三次观察、跨度至少两秒后，才记 `Sent` 并回写任务/包裹账本。
4. 再次失焦、原窗口/进程变化、无法恢复、OCR 或消息状态不明，仍保持结果未确认，禁止自动重发。生成失败/发送前失焦不使用这条发送后恢复逻辑。
5. 窗口恢复与业务状态分开：普通失败或结果未确认，也可回到原工作窗口，不再必须把企微留在最前面。若核验恢复时用户已经切到有标题的另一页面，核验后回到那个页面；结束时用户已经离开企微，则不抢回焦点。最初工作窗口已关闭时不猜测替代窗口。
6. ESC、安全验证/登录验证使所有桌面操作停止，包括只读恢复和 finally 中的切窗口。切回失败不覆盖已确认的发送结果，也不产生二次发送。

出现“已按发送键，成功核验期间再次失焦”等提示，含义是**消息可能已发出但无法确认**，不是“没有发送”。用户应在对应群核对完整运单和本账号完整拦截消息；不能点击发送重试来解除此类暂停。

## 已发任务的对账

历史 `SendPressed` 不因为升级自动清除。逐项核对本账号消息、精确群名、完整运单/正文和账本计划哈希，保留本机审计；确认确已发送后，通过原 `desktop_sender_cli --apply --confirm-sent <task_id>` 在 `DesktopSendProcessLock` 内对账。不调用真实发送网关，不直接删 JSONL/数据库行，也不改变同包裹永久防重保护。

本次单笔对账不等于平台已退款、客服已接受拦截、包裹已退回或 ERP 平账。那些状态仍由原有独立核验决定。真实单号、客户和聊天证据只保存在 Git 忽略的 `.runtime/audits/`。

## 部署及验证

在当前已验证的 worker 快照上仅覆盖 `workflows/windows_wecom.py`，同时保存配套测试和本说明，不覆盖开发中的 `module1_worker.py` 等脏改动。无需安装新依赖、修改环境变量或迁移数据库；不用重启 Web。

发布前备份 worker 版本指针、发送 JSONL 和关键任务状态，暂停守护并请求 worker 自然结束当前周期；禁止强杀执行中的资金任务。停止后登记已核实任务的发送结果，切换到新独立目录，重新启动 worker 和守护。保留所有防重账本。回退仅回到原 worker 代码指针，不能还原旧发送账本而让已发消息重新入队。

相关测试：`test_wecom_focus_recovery.py`、`test_windows_wecom.py`、`test_wecom_receipt.py`、`test_desktop_sender.py`、`test_desktop_foreground_retry.py` 和 `test_parcel_notice_store.py`。全部使用隔离夹具，不向快递群发送测试消息。真实群只读核对与模拟失焦测试分开记录，不能把单元测试通过说成已做真实批量发群验收。
