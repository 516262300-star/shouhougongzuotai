# ERP欠货查询空状态与明细完整性修复（2026-09-11）

## 发现与影响

生产模块3持续报“ERP欠货表结构不完整，不能视为无欠货”。使用既有客户身份反查，只读获取原始页面并对照两个客户档案，确认旧ERP在状态表为空时省略欠货表头，仅在`状态表订单`页签内保留完整空容器和`总计：0`。旧代码拒绝所有缺表头页面，因此把这一明确空状态也标记为查询不可用。页面里的另一个延迟加载链接属于采购车，不是欠货数据源，本修复不调用该链接。

同时确认旧通用表格解析会跳过列数不完整的首行，或在遇到后续残缺行时提前结束，还可能只读取第一个欠货表。残缺行、后续表中的欠货可能被遗漏，影响无欠货判断。

## 修复边界

- 仅适配完整的已观察空状态：唯一的`状态表订单`页签、唯一且完整闭合的`home`状态区域、空的`cart`容器、唯一明确为零的总计；未知文字、加载脚本/iframe、重复区域、缺标记、非零总计、截断页面均拒绝。
- 明确权限失败、授权过期、查询失败和超时提示不得按空页处理。网络超时仍返回`unavailable`。
- 有欠货表时逐表、逐行读取。表头重复、不完整、错列、合并单元格、未闭合、明细身份缺失、重复明细或加载提示均阻断，禁止跳过残缺行；后续欠货表不能被忽略。
- 无欠货只提供一项核验事实。标记ERP完成仍须经过原有的客户身份、售后号、金额、唯一退款流水和累计应收归零等校验；缺资金流水或应收未归零不会完成闭环。
- 不改变平台白名单、资金幂等、历史失败任务状态或ERP写请求次数；不通过退款/补单写操作验证解析器。
