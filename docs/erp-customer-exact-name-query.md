# ERP 客户档案精确名称查询

2026-09-30 复核归属查询误报后修正。

ERP 的 `GetCustomerName` 返回值中，`autocomplete` 第一段既是客户名称，也是 `stdview?autocustomer=...` 的精确查询键。部分真实名称以全角空格 U+3000 开头。程序先对它调用 `strip()`，会打开另一份查询结果或空档案页；空页没有销售链接，原校验又把这种情况统一报为“客户 ID 不一致”。这不能证明 ERP 原始客户资料关联错误。

客户销售查询现在只用 `strip()` 判断名称是否全空，不改变发往 ERP 的原始名称。客户唯一性、档案中销售链接的客户 ID、全部销售分页及目标平台订单号仍须核对。没有可核验的销售链接时，明确返回“ERP 客户档案未返回可核验的销售页链接”；实际 ID 不匹配仍阻断。不得绕过档案核验、按相似客户名选择结果或用客户档案归属替代销售单业务员。

本次只修复查询键与错误说明，不修改 ERP 客户名称、不修改销售单，也不执行退款或补单。个案重新读取完整销售页，核实目标订单的原销售业务员后，仅更新本地归属缓存，保持业务时间与退款字段不变。原查询、两种名称对应的档案页、完整销售核验结果、缓存前值及发布基线保存于 Git 忽略的 `.runtime/audits/erp-customer-link-20260930/`。

测试覆盖全角/普通首尾空格、正常名称、全空名称、缺少销售链接、真实客户 ID 不一致，以及归属、整包裹数量和长销售分页回归。后台发布从当前正式版本复制，只替换 `integrations/erp/package_orders.py`；等待旧后台自然结束并由现有守护任务恢复，网页版本与自动化开关保持原配置。回退使用私有审计中的原始后台 release 指针，仍须自然停止当前周期。
