# 新挂机电脑企微重启与弹窗遮挡修复（2026-09-24）

迁移后的本次连续失败来自同一条已按发送键的通知：第三方应用商店置顶弹窗遮住原消息正文，导致无法取得完整发送回执。后续周期只读回查同一任务，没有重复发送。新机重启后企微停在未选中群聊的欢迎页，旧回查路径无法自动定位原群，进一步延长阻塞。

## 处理与运行规则

- 用户已在新挂机电脑卸载联想应用商店并重启。后台仍由原来的 Module1 Watchdog 启动，周期、账户、白名单和业务配置保持原值。
- `WindowsWeComGateway.verify_existing_receipt` 在发送锁与原任务身份校验内，通过已核验焦点的群搜索框输入原群名。选择结果前再次确认搜索框焦点；打开后连续两次核验完整群名与空输入框。
- 此路径只定位群聊和查看消息，不输入通知正文、不调用发送钩子、不清空或发送原草稿。遇到草稿、群名不符、失焦、安全验证、ESC 仍停止。
- 已在原群时保留当前历史位置，避免每轮搜索都回到最新消息而无法找到隔夜通知；只在欢迎页或其他群时定位原群。选择搜索结果后只恢复原主窗口，处理同进程群公告窗口抢焦点，随后重新核验。
- 截图前后检查企微上方的可见第三方窗口。遮挡期间明确报遮挡，不能把遮挡截图当成消息不存在，也不继续向旧历史滚动。不会关闭第三方程序或弹窗。
- 使用已测试的逐格历史滚轮实现，每格派发期间保持鼠标位置；仍最多回看 8 次、90 秒，不做无限历史搜索。
- 恢复成功必须有原群内唯一的本账号完整正文气泡、空输入框、明确发送状态，连续至少三次且跨两秒；不依赖快递回复。通过后由原 `recover_send_pressed` 持久化证据并完成原任务，保持原尝试次数。
- 未获证据时保留 `SendPressed` 和防重阻塞；不得清账本、把部分正文或快递回复当成功、直接重发结果未知的通知。
