# 淘系拦截：历史订单阻塞与持续失败提醒

## 原因

原核验会先读取同一客户历年全部原销售订单的完整平台详情，再比较运单。无关旧订单详情过期或无权限，可能在尚未核对当前运单前阻断整包裹检查。通知任务已生成但未进入企微，五分钟重查又覆盖失败时间，持续失败没有升级人工待办。

## 修复后的核验

先核实目标店铺及目标平台交易身份，完整读取ERP客户原销售分页。逐笔优先核对官方运单；明确不同运单的订单无需再读取无关完整交易。相同运单和快递公司的全部交易仍逐笔核验子单、SKU、数量、金额和有效全额仅退款，保留证据时效、快照、防重及人工锁。

历史物流正常返回空集合时，仅在以下条件同时满足时按已完成发货批次排除：

- 原销售分页、订单身份完整，目标及旧订单的每条RC原销售均有可解析完成时间，RC编号日期与完成日期一致。
- 目标全部RC完成时间在平台本次发货时间之前24小时内；旧订单最后一次RC完成时间比目标最早完成时间早至少90天，没有近期补发记录。
- 官方物流响应具有请求编号、无错误、无未知字段、无后续页且总数为零；本地没有已知同运单关联。

这是完整已完成发货批次的排除依据，不表示找回了旧运单。仅凭旧订单号、日期久远、空物流或接口异常均不能排除。目标订单本身、已知同运单、近期补发、缺日期、RC日期冲突、分页不完整和平台错误仍停止发送并重查。审计记录保存所用时间、平台空结果及90天边界。

## 持续失败处理

淘系整包裹技术核验失败保留第一次失败时间和连续次数，每五分钟重查；连续至少3次且持续至少30分钟转“整包裹关联仍无法核实、拦截通知尚未发出”人工待办，由原销售业务员跟进，提醒已人工发群时勿重复发送。成功核验清除连续失败起点。

沿用原业务员归属复核、待办查重及发布回执；未确认归属时不冒充已送达。取消的仅为尚未进入输入/发送的原待发任务，已发送、已输入或结果不明凭证保留。人工接手后不自动解除人工锁。此超时升级只适用于天猫/淘宝，不改变其他平台的异常策略，也不扩大自动退款权限。

## 验证与维护

本地290项相关测试通过，覆盖淘系历史批次、同包裹退款、原业务员分派、平台通知保护、无轨迹、桌面发送、防重及队列公平性。真实订单只读预演通过整包裹检查。个案订单及完整证据仅保存在Git忽略的 `.runtime/audits/intercept-missing-20260927/`。

发布候选从新正式机正在运行的Worker复制，仅叠加三个源文件的本次差异，保留正式机已有抖音及其他修复。正式候选离线验证、旧周期安全结束、验证备份后切换Worker；Web及独立揽收提醒指针保持原值。消息是否送达须核验原任务、发送账本和包裹凭证，不以生成任务或核验通过代替发送成功。没有新增资金请求、数据库迁移或定时任务。

回退应保留原发送账本、包裹凭证与人工锁，并先停止通知消费，不能删除凭证再重发；旧版本仍有历史订单阻塞风险。
