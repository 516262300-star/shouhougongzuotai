# 企微长草稿已输入但未发送：输入框布局修复

## 原因

群名核验已通过，但消息输入后停在 `PasteStarted`。实际异常为“无法唯一定位企微输入面板”：原算法只读取窗口高度 90% 处的一条白色扫描线，换行草稿覆盖该行后，文字把白色背景切断。窄窗口同时使输入框滚动隐藏消息首行，完整草稿核验也不能通过。

## 修复

- 从输入区域多个高度寻找至少重复三次的最宽完整边界，拒绝只有一条白线或边界不唯一的画面，不把文字间白缝当作完整面板。
- 根据实测输入面板上下边界计算草稿范围，避开工具栏和发送按钮。最大化时面板高度基本固定，不能继续按整窗高度裁剪首行。
- 激活企微时先最大化主窗口，再搜索群、核对草稿；只展开目标企微窗口，恢复其他窗口焦点时不改变其尺寸。
- 仍需完整群名、完整运单/正文、空框及唯一发送回执核验。草稿被裁切、识别失败、发送结果不明时继续暂停，不把 `PasteStarted` 降级成可自动重发。

## 验证与恢复边界

相关发送器、群名/草稿/回执、前台恢复和人工恢复测试共 79 项通过。实际故障画面重放后能正确定位面板，但仍拒绝首行不可见的草稿；展开窗口后的同一草稿完整识别通过，`group_matches=true`、`draft_matches=true`、`input_empty=false`。

现场核对发现原运单已由快递方在正确群明确回复已登记，故不重复发送。保存原草稿画面、账本备份和核验证据后，只清除与该任务全文完全匹配的草稿，复核空框，再通过既有 `ManualHandled` 流程记录人工已通知。确认的是通知/登记事实，不是实际拦截成功或允许退款。
