# 售后状态展示修复（2026-09-08，第二批）

## 适用边界

本批修正售后订单列表、详情、在途拦截退款提示及汇总统计，接口仍为只读。没有修改平台同步频率、退款执行开关、ERP 写入权限或发送账本，没有新增自动认领，也不会因为页面显示“待确认”而重新发起退款。

平台退款成功、仓库验货通过、ERP 退货平账是三个独立事实。完整拦截闭环仍需退货单匹配到客户名下并核验平账；不能把平台退款成功当作售后闭环。

## 平台退款结果

- 六个平台优先使用同步入库的 `refund_financial_status=SUCCESS`；兼容旧拼多多记录的售后状态 `10` / 订单退款状态 `4`。这两个数字不会套用于其他平台。
- `RETURN_INSPECTED_PASS` 等本地业务流程不再作为平台已退款的证据。
- 同意退款任务完成、但尚未取得平台成功结果时，显示“已提交·待平台确认”。
- 平台明确关闭显示“退款已关闭”；没有明确成功结果显示“待平台退款”或“平台状态待确认”。不猜测未知平台数字代码。
- 顶部原“已完成”更名为“平台已退款”，统计、列表、详情和拦截页成功判定一致。该数字不是 ERP 闭环数量；闭环进度仍在“在途拦截”查看。
- 已验货但尚未退款的记录仍保留在工作台待处理范围；明确关闭且无其他待执行事项的记录可在“全部售后”查询。已退款或明确关闭的记录不再计入退款冻结筛选。

## 退款范围

比较基准仍是买家优惠后实付金额，而不是商家应收。平台补贴不计入买家实付比较。

| 页面提示 | 含义 |
| --- | --- |
| 全额退款 | 正数申请金额等于买家实付 |
| 部分退款/补偿 | 申请金额大于零且小于买家实付，保留售后记录但排除全额退款拦截 |
| 缺买家实付 | 缺少比较基准，无法判断退款范围；可能平台早已退款 |
| 金额异常 | 非正数或申请金额高于买家实付，需核实原始订单 |

本批不回填缺失金额，不使用申请金额反推买家实付。零元申请不会被全额退款展示筛选纳入。

## ERP 客户归属

| 页面提示 | 含义 |
| --- | --- |
| 待查询 ERP | 当前范围内尚无本地查询结果，等待后台分批处理 |
| 历史单未查询 | 天猫订单早于 `TMALL_MODULE123_MIN_ORDER_ID`，没有查询缓存 |
| 归属同步未开启 | 对应业务链路或 `ERP_SALES_OWNER_SYNC_ENABLED` 未开启 |
| ERP 查询未配置 | 缺少 ERP 只读连接或已启用的网页登录凭据 |
| 归属查询未接入 | 当前平台尚未纳入客户归属查询，并非售后订单同步失败 |
| ERP 未查到客户 | 查询成功但未找到该订单客户；不等于接口故障，也不证明未发货 |
| ERP 客户未设置业务员 | 查到了客户，但没有取得业务员，需核对归属 |
| ERP 查询失败·待重试 | 最近一次查询没有取得有效结果，等待后台优先重查 |
| 快速退款未入 ERP | 拼多多未发货仅退款已成功、查询成功且无客户结果；是规则分类，不等于已核验 ERP 平账 |

已有缓存优先展示，不因调整起始范围而丢失既有匹配。详情新增归属说明、最近查询时间、退款范围说明、平台退款结果及说明；列表悬停可查看原因。按售后单标识组装归属缓存，防止不同店铺/平台相同订单号互相覆盖显示。

列表和详情不再实时逐单调用 ERP。归属查询继续由原后台同步负责，批量与刷新时间仍分别由 `ERP_SALES_OWNER_SYNC_BATCH_SIZE`、`ERP_SALES_OWNER_REFRESH_SECONDS` 决定。2026-09-08 后续更新增加[到期失败单半批优先重查及指定订单刷新](erp-owner-retry-20260908.md)，配置数值不变。关闭后台同步时，反复刷新页面不会补齐缺失归属。查询失败缓存目前只存状态和调度时间，没有原始错误文本，因此页面给出排查方向，不虚构具体根因；新发生的网页登录查询故障在本地日志记录脱敏原因类别。

## 升级与验证

本批无数据库迁移，无需改动 `.env`。更新后运行后端回归测试、前端 `npm run build`、`npm run test:sites`，重启本机 Web 服务并核对 `/health/ready`、售后列表和样本详情即可。后台动作运行器无需为本批重新启动；不要中断正在执行的平台退款或 ERP 请求。

新增 `tests/test_record_status_consistency.py` 使用独立 SQLite 内存数据库和禁止外部查询的测试替身，覆盖跨平台成功口径、未知状态、验货通过未退款、已提交待确认、金额比较、归属缺失原因和真实路由只读验证。运行测试时若系统临时目录不可访问，可使用工作区 `.runtime/` 下全新且唯一的 `--basetemp`，不要指向已有业务文件夹。

本机继续部署，不将 ERP 或售后数据发布到云端。对应 Notion 说明页当前没有可用连接器，此前页面加载亦超时，本批先将说明同步到 README 与 GitHub，Notion 尚未更新。
