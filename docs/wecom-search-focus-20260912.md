# 企业微信切到前台后不搜索群的修复

## 原因与修复

2026-09-12 本机复现：Ctrl+F 已打开左上角搜索框，但旧代码将整窗缩至 96×54 后计算变化量，实际仅为 0.001807，低于 0.002 阈值。因此出现“未检测到企业微信搜索区域变化”，停在输入群名之前。搜索框原本已打开时，同样不应要求画面再次变化。

改为识别左上方搜索框完整的蓝色焦点边框，要求上下水平边及左右竖边吻合，不用聊天区变化替代焦点证据。直接在原图检测，兼容窗口边框和高分辨率，避免缩图抹掉细线。搜索框已聚焦时立即继续；Ctrl+F 至多尝试两次，每次等待最多 2.2 秒，确认焦点前不输入群名或消息。

两次均未确认搜索框就绪时，记录输入前暂停并安排 60 秒冷却，后台下次到达发送阶段时持锁检查任务仍为 Pending，再完整重试。因此实际间隔可能超过 60 秒，取决于当前业务周期耗时。前台临时失焦沿用相同机制；错误提示保留实际原因，不再把搜索失败显示为前台激活失败。

窗口切换期间 Windows 可能返回空前台句柄，现在按无前台窗口处理，避免 `int(None)` 导致未知异常暂停。无前台不能当作企微已激活，后续输入仍需通过原窗口和安全验证检查。

ESC、安全验证、已有草稿、无法识别聊天布局等失败仍暂停。持久化账本显示已开始输入或已按发送键的任务不降级为可重试；完整群名、草稿及发送后消息的连续核验保持不变。鼠标高亮或其他覆盖物影响画面核验时，将鼠标移到聊天列表后再处理，不忽略未知画面内容。

## 验证与实际验收

109 项相关测试通过，覆盖已聚焦但不变化、延迟聚焦、两次搜索超时、非搜索蓝色区域/残缺边框、窗口边框和 200% 缩放、空前台句柄、ESC/安全验证、发送前冷却及输入后防重，包含既有回执和数据库幂等回归。Ruff 定向检查通过。

真实搜索框截图的未聚焦/已聚焦、含边框/主窗口、原尺寸/200% 缩放共 8 个用例通过。截图及个案证据仅存放于 Git 忽略的 `.runtime/audits/wecom-search-20260912/`，不提交群聊内容或运单信息。
