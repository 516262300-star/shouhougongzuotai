# 企业微信输入前失败自动重试

## 行为与边界

企业微信前台激活、搜索焦点、群名稳定性失败原已支持自动重试。本次补齐消息正文尚未输入时的截图和界面识别异常，以及暂时找不到可见主窗口的情况。上述失败持久化为 `PausedBeforePaste` 并记录 `retry_after`，冷却 60 秒后在下一个正常通知周期重新核验；仍不可用则再次冷却，无需人工逐次点击。不是保证恰好 60 秒发出，后台周期和平台核验耗时仍会影响实际时间。

入口保持原 Module1 Worker 与原桌面守护任务，无新增计划任务、配置项或外部 OCR。数据库任务必须仍为待执行企微通知，自动恢复在原发送互斥锁内进行；每次重新经过平台实时资格、目标群白名单、运单包裹永久账本及已发送防重。

若停留在全局聊天记录搜索窗口，仅在本地 OCR 同时识别顶部“联系人、群聊、聊天记录”和底部 `Ctrl+Tab`、`Esc 关闭窗口` 导航提示时，输入正文前按一次 Esc 关闭该页，再重新激活核验主窗口、搜索目标群。不会点击历史搜索记录、邀请链接或清空聊天草稿。搜索结果中的群名不能代替完整聊天标题。

原输入保护继续执行：连续两次完整群名一致、输入框空白、无相同消息气泡后才输入正文。用户主动按 Esc、安全或登录验证、现有草稿、多个同尺寸窗口、未知异常仍保留人工处理。持久化进度已到 `PasteStarted` 或 `SendPressed` 时，即使底层抛出可重试错误也不能降级重发；已按发送键的任务仅沿用原只读回执核验。

运行监控的恢复信息区分自动重试与人工核验，返回 `automatic_retry` 和 `retry_after`，已安排自动重试时明确提示无需点击。原人工重试入口保留，供确需立即重新检查使用。

## 历史记录恢复与部署

旧版本没有 `retry_after` 的暂停记录不按错误文字批量解锁。当前个案须在维护窗口持发送锁，核对所有历史均未进入正文输入、动作仍待执行且未尝试、无包裹输入占用、原方案哈希与输入前失败审计一致后，单独追加自动重试到期时间。保留全部原历史；个案身份、截图与核验结果只存 Git 忽略的 `.runtime/audits/`。

发布基于正式机 Worker、Web 各自当前版本，仅覆盖本次文件。原 Worker 自然结束、Web 优雅退出并完成数据库及运行账本验证备份后切发布指针，由原桌面 Session 1 守护恢复；不修改资金开关、独立揽收提醒指针或数据库结构。回退也需安全维护窗口并保留全部新旧发送账本，不能删账本绕过发送结果核验。

## 验证

回归覆盖冷却前不重试、到期自动恢复、再次失败重新冷却、非待执行任务不重试、已输入或按发送键的任务不降级、旧暂停不批量恢复，以及搜索页识别和监控提示。实际失败截图仅离线核验页面识别，不把截图提交到仓库，也不额外发送测试消息。
