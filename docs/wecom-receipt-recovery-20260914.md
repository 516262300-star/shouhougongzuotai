# 企微发送后自动复核与恢复

## 本次查明的事实

2026-09-14 一条极兔拦截通知在10:08:58按过发送键，10:09:20回执核验失败，账本停在 `SendPressed`。现场只读截图中，正确群内存在完整自身发送消息，输入框为空，客服在10:16回复已登记拦截。使用原有严格连续核验再次检查通过后，确认原通知并核销关联任务，未重新发消息或发起资金请求。

旧代码没有保存超时时每项判定和识别耗时，因此无法追溯当时具体是群名、正文、输入框、状态还是时间不足造成失败。确定存在的恢复缺口是：进入 `SendPressed` 后后台直接返回阻塞，不会再次读取原消息，临时识别问题因而持续等待人工。

## 新行为

- 发送后连续核验预算由12秒增加到45秒，仍需完整群名、唯一自身完整正文、空输入框、正常发送状态连续三次通过且跨度至少两秒。已有一次失焦恢复仍最多执行一次，并重新给予45秒；输入过程中不争抢焦点，不降低OCR置信度或模糊匹配运单。
- 后台发现 `SendPressed` 时，在原桌面发送锁内自动只读复核当前群。只激活企微窗口、读取画面、恢复原窗口，不搜索、不输入、不粘贴、不按发送键。
- 复核前后核对任务身份、原计划哈希、目标群、运单、数据库包裹凭证。严格回执通过并留档后完成原任务，再解除账本阻塞；同一业务周期可继续原通知队列。
- 单任务复核记录带至少60秒间隔，下次实际复核由后台周期触发，不承诺每60秒执行一次。进程重启后也保留间隔。`PasteStarted`、用户ESC停止、安全验证、身份变化和证据缺失继续阻断。
- 当前群已被用户切换、原消息已不可见或确实存在发送异常时，仍需核对原群，程序不猜测成功。该版本保留全局未知发送保护，不将未知结果清空后放行其他任务；自动恢复解决有完整证据的临时未确认。

## 诊断与维护

- `.runtime/audits/desktop-receipts/` 保存各任务首次失败和最新复核的截图/JSON，包括逐次群名、输入框、消息数、状态判定和OCR耗时。每个任务保留首败及最新文件，不因每次复核无限新增截图。
- `.runtime/audits/desktop-receipt-recovery/<任务ID>.json` 保存自动复核计划哈希、时间、下一次允许检查时间、判定证据和结果。恢复前后不增加消息发送次数，也不触发退款。
- 以上截图可能包含群内业务资料，属于运行机受保护的审计数据，不提交GitHub。
- 本次现场证据、原账本和发布核验位于 `.runtime/audits/receipt4969-20260914/`。曾经的人工确认只处理该原通知，不能作为后续任务成功证据。
