# ERP 客户端登录与售后工作台接入

## 使用方式

正式机使用桌面的“ERP客户端登录”。客户端第一次登录时在浏览器中完成原 ERP 员工账号授权；工作台继续使用同一个员工的权限。以后由客户端恢复登录和续期，工作台不保存、提交或回退使用 ERP 账号密码。

客户端应在新挂机电脑当前 Windows 用户下运行。计划任务 `Leedis ERP Login Client` 在该用户登录 Windows 后启动；窗口可以留在后台。请勿点击“退出登录”，也不要关闭客户端。正常重启后需要先进入 Windows 桌面，客户端才会恢复。企业微信发送仍要求该电脑未锁屏且企业微信在线。

客户端显示的“自动登录剩余”是本次授权总期限，最长 30 天；到期、撤销授权、账号切换或凭据失效后，须在客户端重新登录。普通网络波动时客户端按原有退避续期，工作台保留原任务下次核验。客户端不可用不代表没有退货或客户，也不会改变已完成的退款或消息回执。

## 工作台配置

```dotenv
ERP_WEB_BASE_URL=https://ldswj.net
ERP_WEB_AUTH_MODE=desktop
ERP_DESKTOP_BRIDGE_FILE=C:/Users/<执行用户>/AppData/Local/LeedisDesktop/workbench-<客户端路径标识>.json
ERP_DESKTOP_USER_ID=<原ERP员工数字ID>
```

上述文件名由客户端完整 EXE 路径的小写字符串计算 SHA-256 后取前 16 位生成。移动或改名 EXE 后要重新核对桥接文件路径。配置文件只能保存文件路径和员工数字 ID，不能复制桥接文件中的随机连接凭据到文档或环境变量。正式配置移除 `ERP_WEB_USERNAME`、`ERP_WEB_PASSWORD`。保留 `ERP_WEB_LOOKUP_ENABLED` 及现有业务、写入、发布开关原值。

程序默认 `ERP_WEB_AUTH_MODE=password` 只为兼容未迁移环境。配置为 `desktop` 后，即使误留旧密码也不会调用密码登录，失败时也不降级。业务后台、Web、独立揽收提醒以及人工待办、历史只读补查等入口必须同时更新后再切换配置。

## 凭据边界

- 原客户端通过 PKCE 完成浏览器授权，访问凭据仅在内存，续期凭据由原客户端写入该 Windows 用户的凭据管理器。
- 增强版客户端增加本机回环接口 `/session`。文件 ACL 只授予执行用户和 SYSTEM；请求需要随机连接凭据、正确本机 Host，且拒绝网页 Origin。它不监听局域网。
- 后台只取得指定 ERP 员工的一次性网页登录票据，单次 POST 到固定 HTTPS `/desktopauth/enter`，确认 ERP 会话后使用内存 Cookie。账号访问凭据和续期凭据不导出给工作台。
- 票据申请和客户端登录、续期、退出共用一个串行执行器，防止续期凭据轮换竞争。后台每次使用会话前检查客户端账号状态，客户端退出、换账号或不可用会停止使用缓存会话。
- 票据消费结果不明时不重放该票据，不因此重试资金操作。原退款、认领、人工待办及企微的幂等保护和回查规则继续生效。

这一方案减少长期 ERP 密码在自动化配置中的保存，不代表执行用户账户被入侵后仍能保护其登录会话。已有旧配置备份按原凭据备份权限管理，不向 Notion、GitHub 或日志复制。

## 验证和恢复

先检查客户端显示原 ERP 员工，再执行只读登录探测，确认会话和待处理退款、退货列表可读取。不要通过发送测试待办或实际退款验证登录。

客户端异常时，在新挂机电脑重新打开该客户端并完成登录；不要同时启动两个不同版本，也不要启动额外续期脚本。后台按原周期核验。若报告账号不一致，恢复绑定的原员工账号，不能通过随意修改员工 ID 绕过校验。

更新时分别基于三个正式入口的当前发布源生成候选，保留各入口已有修复；等待业务周期和独立提醒退出后再更换配置和指针。环境配置备份使用受 ACL 保护的本机 DPAPI 加密文件。回退代码必须支持客户端登录，禁止直接恢复含旧密码的配置或清空执行账本。

源码和构建方式见 [客户端维护说明](../tools/leedis_desktop/README.md)。真实账号、配置、部署哈希及验收证据保存在 Git 忽略的 `.runtime/audits/erp-client-login-20260929/`。
