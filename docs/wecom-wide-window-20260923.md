# 新正式机宽屏企微群名识别修复

新运行机企微窗口为 1924×1036。原算法从窗口宽度的 20% 开始寻找白色输入面板，但固定宽度的左侧栏在该窗口上不足 20%，导致面板左边界被误认，群名左侧被裁掉。发送器在输入前拒绝继续，现场没有粘贴或发送。

本次从完整窗口宽度定位面板，仍要求多条扫描线重复出现、唯一最宽面板、边界完整。贴边截断的白区仍拒绝识别。完整群名精确匹配、草稿全文校验、发送回执和永久防重保护均保留；不删除或改写已有发送账本。

验证包含固定侧栏的三种宽度、位于原扫描起点左侧的非空草稿、错误群拒绝、截断面板拒绝，以及现有窗口识别、群就绪、输入前重试和发送后恢复测试。39 项回执测试及 44 项关联测试通过。现场保存截图的离线 OCR 已读取完整目标群名，输入框确认为空；离线检查没有操作企微界面或发送测试消息。

发布时只复制当前正式 Worker 版本并替换这一文件，保留同期其他业务修复。先取得守护周期锁、请求正常停止并等待整个 Worker 进程树退出，核对原指针未变化后原子切换新版本，再通过交互桌面守护恢复。回退代码也必须保留切换后业务数据及发送凭证。

首轮修补后群名校验通过，但原有通知在完整草稿OCR环节继续被拦截，尚未按发送键。检查发现草稿仍读取归一化后图像，而气泡已读取原始像素；宽屏上先缩小再放大会丢失字母及笔画。后续修补让草稿也读取原始像素，继续逐字匹配完整正文和运单号，不降低OCR置信度。新增原像素保留及错误运单拒绝回归测试。已输入草稿保持原有阻塞记录，不能因修补而自动清空、重发或冒充已发送。

第二版84项相关测试通过，17:03安全切换到 `wide-wecom-worker-20260923-v2`。新机交互账户下的只读诊断连续三次核对1924×1036原截图，群名与完整草稿均严格匹配，计划哈希未变、没有相同消息气泡；诊断未输入或发送。原草稿需用户确认发送并核实实际回执后，才能使用既有人工确认流程解除阻塞。个案正文、运单、截图和诊断结果只保存在受保护的审计目录。
