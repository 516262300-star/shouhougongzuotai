# 淘宝退款与模块1/2/3限定自动执行（2026-10-08）

## 范围与上线口径

用户明确要求开通现有淘宝C店的退款权限、模块1拦截退款及退回平账、模块2验货退款、模块3未发货平账，并明确包含现有待处理订单。普通订单发货20小时无物流提醒沿用已上线的独立巡检，不重复新建任务。

本次新增淘宝专用执行器，严格使用淘宝官方HTTPS POST，不用第三方中转，不伪装成天猫，不扩大天猫或公共资金执行器白名单。开发机默认关闭；只有正式机独立逐店标记、最新成功同步、身份核验和原有总开关均通过才执行。配置开启不等于积压全部退款或所有复杂场景已支持。

部署验收状态见文末；未完成首轮运行时，页面显示“已配置·等待运行核验”，不得以开关文件代替执行验收。

## 分模块条件

| 能力 | 自动处理边界 |
| --- | --- |
| 平台退款 | 仅白名单淘宝C店；主查询和退款子账号实时同卖家；独立父单、单子单、完整SKU/颜色/数量、全额实付、最新允许状态与退款版本一致 |
| 模块1拦截退款 | 原销售、原收款、包裹唯一后进入既有通知队列；发送仍受原通知/物流/包裹防重闸门限制。**首版实际平台退款必须已有真实正式TH退回**，且处于模块1允许工作时段 |
| 模块1退回平账 | 平台明确SUCCESS，正式TH完整对应原销售与原收款，实收唯一、无欠货、应收精确匹配；单次ERP补单后核对唯一退款流水及零应收 |
| 模块2验货退款 | 正式TH、完整商品一致、唯一实收分配及独立仓库质检PASS都必需；平台已先退款时，ERP核账同样不省略验货要求 |
| 模块3未发货平账 | 本地与官方均明确退款SUCCESS、实付金额相符、明确从未发货、ERP独立整单/原收款/欠货全部一致；只做ERP单次补单，绝不重复平台退款 |

多订单、多包裹、多子单、部分数量/金额、特殊售后、存在争议或人工锁、暂存未认领、关联不唯一均暂停自动处理，按[同客户多包裹核验方法](customer-multi-parcel-return-verification.md)转人工整批核查。不自动把暂存认领成正式TH，不造验货通过，不自动抹差。

用户已确认退款子账号额度20,000元和免短信；程序另外设置单次请求不得超过20,000元的本地保护。账户额度属于用户确认，未通过查询验证其每日/单笔口径；平台仍可因额度、状态或权限拒绝。只对该白名单使用 `ignore_code=true`，不刷新或消费refresh_token。

此前一笔“未收货先退”的真实成功退款是单独授权个案，不纳入自动规则；详情见[退款实测边界](taobao-refund-verification-20261008.md)。

## 入口、状态与凭据

- 入口：`integrations/marketplace/runner.py` 的淘宝本轮同步全部成功后，调用 `workflows/taobao_automation_runner.py:run_automation`；不新增计划任务。后台完整周期仍由原守护管理。
- 默认每轮最多6笔，按 `automation_poll_state` 未查优先、最久未查优先公平轮转。普通等待/业务阻断30分钟后复查，技术异常5分钟后只重新核验；**资金请求不会自动重试**。这些是最早到期时间，不承诺每分钟处理完积压。
- `.runtime/taobao-automation/enabled.json`：版本 `taobao_modules_v1`、模式 `enabled`、`include_existing=true`、逐店卖家ID、退款子账号环境变量引用及五个独立功能开关。缺标记默认关闭；`preview` 模式不会在后台执行。
- `.runtime/taobao-automation/status.json`：版本、配置哈希、真实开始/结束时刻、错误、逐轮候选/等待/阻断/完成/技术异常计数。无报告、过期30分钟、未结束或技术异常时，接入能力不能显示正常开启。
- 主查询使用 `TAOBAO_SHOPS_JSON` 的官方店铺配置；退款令牌只引用被忽略的正式 `.env` 内 `TAOBAO_SHOP_N_REFUND_SESSION_KEY`。网关严格为 `https://eco.taobao.com/router/rest`，禁止环境代理、重定向和请求内重试。
- 继续尊重淘宝同步、模块2/3、ERP业务写、模块1/3 ERP执行的原有总开关。其他平台及普通提醒开关不变。

## 并发、资金与恢复

使用独立MySQL连接级互斥 `lds_taobao_automation_v1` 和 READ COMMITTED；正式执行只允许MySQL永久账本。每笔在请求前重新读取平台/ERP，比较快照及版本；证据过时、变化或不完整则停止。

资金使用公共 `money_operations` 标准平台/店铺/售后/操作唯一键。先持久化 `REQUEST_STARTED`，仅一次请求；明确响应先记 `ACKNOWLEDGED`，只读确认官方SUCCESS或ERP唯一流水后才记 `CONFIRMED`。响应未知记 `UNKNOWN`，重启/再次轮询只回查，不删除或重建资金键。实收同时占用正式TH整包及TH/原销售/SKU两个永久键，其他售后已有占用时不得复用。

正式ERP只使用核验过的原退款记录补单入口；不新建虚假退货、改客户运单或补造库存/质检。平台退款成功、实物验收、ERP平账是三个独立事实。

### 只读检查

在正式应用根目录并加载**当前正式发布源**的Python环境中：

```python
from aftersales_workbench.core.config import Settings
from aftersales_workbench.workflows.taobao_automation_runner import read_status, run_automation
report = read_status()  # 仅读本地运行报告
# 人工维护预演：现有标记为preview/enabled时可用，平台/ERP只读，不占用资金或改订单。
preview = run_automation(Settings(_env_file=".env"), dry_run=True, limit=20)
```

不要在开发机使用正式令牌试写，不把单笔个案脚本变成循环任务。后台状态还需结合 `/health/ready`、接入能力及Worker存活验证。

### 停用与回退

先防止原守护开启新周期，请求Worker自然完成，不强杀正在进行的资金请求；确认停止后备份并将该标记模式改为 `preview`，或关闭指定逐店功能，再恢复原守护。原报告、游标、资金及实收占用账本必须保留。

回退代码前同样安全停机，核验原指针/候选哈希及后续变更，只恢复本次Worker/Web指针和独立标记。不可恢复整份旧 `.env` 或数据库，不可覆盖其他线程的新配置。回退不撤销已经成功的退款，所有不明结果先回查。
