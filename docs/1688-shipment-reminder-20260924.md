# 1688发货20小时无物流提醒

## 范围与规则

按用户“阿里巴巴开通发货20小时无物流提醒”的授权，适配现有 `1688-main` 主店普通订单。只增加ERP原销售业务员的揽收提醒，不调用平台退款、发货、备注接口，不开通1688模块1/2/3资金或ERP补单；不修改其他平台开关和售后业务后台。

复用原独立计划任务 `Leedis Shipment No Trace Reminder`，每5分钟触发；每轮全平台最多核验200笔，运行中不启动第二份。初次回溯最近72小时修改记录，之后6小时窗口、2分钟重叠增量；入库不等于全部物流已核验。

- 列表使用旧源码已经调用的 `alibaba.trade.ec.getOrderList.sellerView`，详情使用 `alibaba.trade.ec.getOrder.sellerView`。专用客户端只允许这两个读取接口，沿用既有应用配置，不新增或展示密钥。
- 平台普通订单列表不含完整包裹发货时间，逐单补读详情；使用 `nativeLogistics.logisticsItems[].deliveredTime` 分别计时，不用下单、修改或整单最后发货时间替代。
- 昵称已脱敏，`sellerOrder=false` 不能作为权限/身份结论。按已核实完整 `sellerAlipayId` 的SHA-256绑定店铺，列表及每次详情都核对；配置不存原始账号值，缺少或身份改变立即阻断。
- 逐包裹核对运单、快递公司、发货状态和商品子单关系。实测极兔的旧编码仍为 `HTKY`，不据此误用百世；使用明确快递公司名称解析为工作台物流接口标识，未知公司保留核验。
- 满20小时且快递100有效响应明确无任何轨迹，再核对最新订单、退款、包裹和原销售业务员才发布。验证码、未知快递、查询错误、顺丰缺逐运单电话及ERP归属不明都不能当作无物流；没有符合条件的包裹不制造测试消息。
- 已完成、取消和已确认收货（含已收货未结算）不再催揽收，但不因此登记退款或ERP平账。订单实际退款汇总的元/分字段须相互一致；明确全额退款排除、部分退款继续剩余履约包裹，字段冲突等待核验。已结束子单单独所属包裹不再提醒。
- 复用同包裹/快递/业务员合并、发送前二次核验、永久防重和UNKNOWN只回查；已发后出现轨迹退出日常列表，保留原ERP发送凭证，不声称撤回已发事项。

接口字段参考[阿里云1688 API参考](https://alibaba-pdf.oss-ap-southeast-1.aliyuncs.com/1688%20Cloud%20Hub%20API%20Reference-0723.pdf)及[阿里官方订单状态说明](https://developer.alibaba.com/docs/api.htm?apiId=42526)；以正式机真实响应交叉核对，文档中的示例数据不能代替本店身份或包裹证据。

## 配置、入口与恢复

新增两个独立配置，默认关闭：

```dotenv
ALIBABA_1688_SHIPMENT_REMINDER_ENABLED=false
ALIBABA_1688_SHIPMENT_SELLER_FINGERPRINTS={}
```

正式启用还需要兼容独立提醒及Web状态版本、提醒发布指针 `platforms` 包含 `1688`、有效工作台店铺、已核实商家绑定、快递100/ERP授权和原人工待办发布开关。提醒本身不要求有售后或开启平台退款。页面“接入能力 → 发货20小时无物流提醒”按上述条件显示，不仅凭代码存在显示已开启；事项位于“人工待办 → 发货20小时无物流提醒”。

发布时从各角色当前正式目录分别增量组装候选；提醒只修改适配器、入口、已发轨迹解除和新增配置，Web只修改提醒状态与新增配置。售后业务后台不切换。停用仅关闭1688提醒独立开关并从当前平台集合移除 `1688`，不覆盖其他平台及后续新增设置；不要整份旧`.env`回滚。

任务同步错误保留原窗口，完整分页成功后才推进游标；逐单物流/归属异常留待重查，不删除异常来制造零错误。回退不得删除监控游标、发送账本、UNKNOWN或ERP原凭证，不重发已有成功事项。
