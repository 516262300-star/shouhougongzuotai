# 京东发货20小时无物流提醒

用户于2026-09-23授权京东两店接入普通订单揽收提醒。规则为真实发货满20小时且经有效查询仍无任何物流信息时，在原管理系统向原销售订单业务员发布人工待办；同包裹、同快递公司、同业务员合并，已有发送凭证不重发。20小时是业务提前提醒阈值，不等于京东统一处罚时限。

## 数据与判断

- 普通订单增量使用 `jingdong.pop.order.search`，按修改时间、20小时窗口加原有重叠分页，查询待收货及待出库（含分批发货）订单。首次回溯最近72小时修改记录；已有历史订单的后续修改仍会进入增量。失败、分页不完整、重复页或总数变化不推进窗口游标。
- `jingdong.pop.order.get` 读取详情，以 `outBoundDate` 或各批 `shipmentTime` 毫秒时间计时；不以付款/修改时间冒充发货时间。分批包裹保留独立时钟，顶层与分批运单、快递公司冲突时暂停核验。
- 京东中转配置中的店铺标签不等于真实 `venderId`。独立提醒另存已核实的真实商家绑定，每一页及详情都验证商家和订单身份；不改其他售后任务的中转标签。
- 物流使用快递100，接受已有真实轨迹或严格核验身份的有效无结果响应。未知快递编号、查询错误、鉴权/电话验证失败、非空未知轨迹不作为“没有物流”。京东公司编号使用独立映射，不借用拼多多编号，也不按运单前缀猜快递公司。
- 本次经真实运单核实的公司编号：1255654极兔、463圆通、3046德邦物流、680414中通快运、467顺丰速运。前四类已取得身份一致的实际轨迹；顺丰身份已识别，但样本查询需要电话验证。现有统一默认电话没有逐运单归属证据，顺丰无结果单继续待核验，暂不能保证自动发出提醒。
- 已完成、取消或配送退回的订单停止催揽收。未发送记录记为 `CLOSED` 并从人工待办排除；已发送记录保留原ERP编号、正文和发送时间。关闭不是退款成功，不能伪造退款依据；结果不明的请求仍保留供只读回查。
- 全额退款成功排除、部分退款继续监控。退款申请接口 `jingdong.pop.afs.soa.refundapply.queryPageList` 的金额为分，审核通过不等于到账成功；售后退款接口 `jingdong.asc.serviceAndRefund.view` 的 `refoundAmount` 为元，核对唯一退款单、成功状态13、完成时间和实付金额。全额审核通过而完成状态未明确时保留后台异常等待核实，不催揽收、不称为已退款。
- 两个退款接口均使用叶字段传参，必须验证业务success、每条订单身份、记录唯一性和完整分页。实际中转曾忽略嵌套查询条件并返回全店退款，HTTP成功不能视为“该订单没有退款”。平台、退款和归属在发布前反复核验。
- 提醒进入现有“人工待办”，不执行退款、ERP资金操作或快递群拦截。未找到原销售业务员不猜人。后续发现轨迹时排除日常催揽收展示，原发送凭证保留。

京东详情的日期字符串与13位毫秒时间均按真实时间解析；首轮巡检已观察到售后退款完成时间返回毫秒数，不能只按格式化日期解析，否则会造成已退款订单反复待核验。

## 运行与配置

沿用 `Leedis Shipment No Trace Reminder` 每5分钟任务，入口 `scripts/shipment-watch-run.py`。当前周期结束后新周期读取新指针，不强停正在运行的业务。单轮最多核验200笔，20—24小时窗口优先，异常按原计划重查；队列、接口限流及耗时可能延迟提醒。

正式机 `.runtime/shipment-watch-release.json` 需配置下列字段。示例身份须替换为实际核验结果，不得直接复制示例上线：

```json
{
  "enabled": true,
  "source_path": ".runtime/releases/jd-shipment-reminder-20260923/src",
  "platforms": ["PDD", "TMALL", "JD"],
  "jd_seller_ids": {"已登记京东店铺代码": "已核实的纯数字venderId"},
  "jd_carrier_map": {
    "1255654": "jtexpress", "463": "yuantong", "3046": "debangwuliu",
    "680414": "zhongtongkuaiyun", "467": "shunfeng"
  }
}
```

复用已有京东、快递100和ERP授权，不新增密钥。仍受ERP写开关和网页人工待办发布开关控制。独立命令行不传附加参数仍只执行原拼多多/天猫；正式计划任务从指针读取京东开关和已核实绑定。诊断 `python -m aftersales_workbench.workflows.shipment_watch_cli --status` 只查本地全部平台账本。

“接入能力”按每店配置和实际巡检展示京东开通状态。检查 `.runtime/shipment-watch-status.json` 的平台、同步错误、落后店铺与最近完整结束时间，及每店游标、待检查订单异常；不能把游标追平当作每笔物流已核验。

## 发布与恢复

提醒及Web分别复制当前正式版本建立独立候选目录，只覆盖本次文件；核验清单哈希及旧指针哈希后才原子切换。保留入口、发布指针、正式说明和运行记录备份于 Git 忽略的 `.runtime/audits/jd-shipment-20260923/`。不改原售后后台指针，不新增迁移，保留所有提醒防重账本。

停用京东可从指针 `platforms` 移除 `JD`；其它平台继续运行。回退提醒时配套恢复已备份入口和兼容指针，并先停止新提醒发布；`CLOSED`、退款、合并及物流解除依据必须保留，不能删除账本来重发。Web回退恢复已备份Web指针并只重启Web。换挂机电脑时迁移原数据库、指针、授权和账本，同一队列只允许一台执行外部发布。

淘宝本项提醒暂未启用：物流权限限制尚未解决，普通售后同步状态不代表支持该提醒。京东专用预警接口当前中转报错，因此本实现直接按普通订单和20小时规则核验，不依赖预警接口。
